## 1. 전제

- M2 `V3__scenario_baseline.sql`, `V3_1__auth_must_change_password.sql`과 M3 `V4__chat_runtime_baseline.sql`이 존재해야 한다.
- M2 시나리오 도메인은 active scenario, `PUBLISHED` version, start node, option, keyword/synonym 조회를 제공해야 한다.
- `ScenarioMatchingCacheInvalidator` 기본 구현은 Noop이며, M3 구현에서는 `ChatMatchingCacheInvalidator`로 교체한다.
- 모든 API는 `ApiResponse<T>` 또는 `PageResponse<T>` 구조를 따른다.

## 7. 실행 메모

- dev 로컬 검증은 `3.개발/cleverchat`에서 수행한다.
- DB 통합 테스트는 Testcontainers PostgreSQL을 기본으로 한다.
- 화면 테스트는 최소 360px, 768px, 1280px 폭을 포함한다.
- 보안 회귀 검색은 빌드 산출물과 테스트 로그를 포함하되 민감정보 샘플은 가짜 값만 사용한다.

## 8. 구현 PR 필수 검증 순서

1. `mvn test`로 단위 테스트와 MyBatis mapper 로딩을 확인한다.
2. Testcontainers PostgreSQL에서 Flyway V1~V4 적용을 확인한다.
3. 세션 시작 → 옵션 선택 → free-text fallback → 피드백 → 종료의 happy path를 통합 테스트로 확인한다.
4. 주민등록번호/카드번호 차단, 이메일/전화번호 마스킹, 로그 원문 미노출을 보안 회귀 테스트로 확인한다.
5. `/chat`, `/chat/{sessionId}`, `/chat/history`, `/admin/chat/recommendations`를 360px, 768px, 1280px 폭에서 확인한다.
6. 만료 배치와 90일 파기 배치는 실제 삭제 전 대상 건수 로그와 dry-run 성격의 검증 쿼리를 먼저 확인한다.

자동화가 어려운 화면 검증은 테스트 결과 문서에 화면 폭, 브라우저, 확인 항목, 잔여 이슈를 남긴다.
