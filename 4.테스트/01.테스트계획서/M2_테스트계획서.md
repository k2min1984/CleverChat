## 테스트 분리 정책

M2 기준 테스트는 기본 단위 테스트와 PIT(Testcontainers 통합 테스트)로 분리한다. PIT는 Persistence/Integration Test의 내부 명칭이며, mutation testing 도구 PIT를 의미하지 않는다.

| 구분 | 위치 | JUnit 5 태그 | 외부 의존 | 기본 `mvn test` 포함 여부 |
|---|---|---|---|---|
| 순수 단위 테스트 | `src/test/java` | 태그 없음 | 없음 (Mockito/POJO/Validator) | 포함 |
| Spring Boot 슬라이스 테스트 (`@WebMvcTest`, `@DataMyBatisTest` 등) | `src/test/java` | 태그 없음 | 없음 (in-memory 컨텍스트만) | 포함 |
| PIT(Testcontainers 통합 테스트) | `src/test/java` | `@Tag("integration")` 필수 | Docker daemon, PostgreSQL 16 이미지 | 제외 |
| 풀 컨텍스트 `@SpringBootTest` + Flyway/MyBatis 실 DB | `src/test/java` | `@Tag("integration")` 필수 | Docker daemon | 제외 |

빌드 설정은 Maven Surefire의 `excludedGroups`와 `it` profile로 분리한다.

```xml
<excludedGroups>${test.excluded.groups}</excludedGroups>
```

- 기본 `./mvnw test`: `integration` 태그 제외, Docker 없이 단위 테스트만 실행
- `./mvnw -Pit test`: `it` profile로 제외 그룹을 비워 단위 테스트와 통합 테스트를 함께 실행
- `./mvnw -Pit -Dgroups=integration test`: 통합 테스트만 단독 실행

새 Testcontainers 기반 통합 테스트 클래스에는 반드시 `@Tag("integration")`을 부착한다.

## 실행 명령어 (Windows 기준)

작업 디렉토리는 `C:\02.Project\02.자바\01.WorkSpace\CLEVERCHAT\3.개발\cleverchat`이다.

단위 테스트만 실행한다. Docker Desktop은 필요하지 않다.

```powershell
.\mvnw.cmd test
```

통합 테스트까지 포함한다. 실행 전 Docker Desktop을 기동하고 Docker daemon 응답을 확인한다.

```powershell
docker info
.\mvnw.cmd -Pit test
```

컴파일과 테스트 의존성 다운로드만 확인한다.

```powershell
.\mvnw.cmd test-compile
```

통합 테스트만 단독 실행한다.

```powershell
.\mvnw.cmd -Pit -Dgroups=integration test
```

macOS/Linux 동등 명령은 다음과 같다.

```bash
./mvnw test
./mvnw -Pit test
./mvnw -Pit -Dgroups=integration test
```

## Docker Desktop 필요 조건

| 조건 | 기준 |
|---|---|
| Docker Desktop | 4.x 이상, Windows는 WSL2 백엔드 권장 |
| Docker daemon | `docker info`가 오류 없이 응답 |
| 이미지 수신 | `postgres:16` 이미지를 pull할 수 있는 네트워크 또는 사내 미러 |
| 포트 | Testcontainers가 할당하는 임시 호스트 포트 사용 가능 |

Docker Desktop 미기동 또는 미충족 시 예상 실패는 다음과 같다.

| 환경 상태 | 표면 증상 | 원인 |
|---|---|---|
| Docker Desktop 미설치 | `Could not find a valid Docker environment` | Testcontainers가 데몬 소켓을 찾지 못함 |
| Docker Desktop 설치 후 미기동 | `Cannot connect to the Docker daemon at npipe:////./pipe/docker_engine` (Windows) / `unix:///var/run/docker.sock` (Linux) | 데몬 프로세스 미실행 |
| 데몬은 기동되었으나 WSL2 백엔드 비활성 | 컨테이너 생성 단계에서 hang 또는 시간 초과 | WSL2 통합 비활성 또는 리소스 부족 |
| 사설망/프록시로 `postgres:16` 미수신 | `pull access denied` 또는 `i/o timeout` | 이미지 미러 미설정 |
| 호스트 5433 점유 | dev 프로파일 부팅 실패, 통합 테스트는 영향 없음 | Testcontainers는 무작위 포트 사용, dev compose만 충돌 |

진단 절차:

1. `docker info`로 Docker daemon 응답과 exit code 0을 확인한다.
2. `docker run --rm hello-world`로 컨테이너 기동 가능 여부를 확인한다.
3. `docker pull postgres:16`으로 이미지 수신 가능 여부를 확인한다.
4. 위 단계가 모두 정상이고도 실패하면 코드 결함으로 보고 결함 티켓을 등록한다.

## CI 실행 전략

| 단계 | 명령 | Docker 필요 | 실패 처리 |
|---|---|---|---|
| `build` | `./mvnw -B -DskipTests package` | 아니오 | 즉시 실패, 후속 단계 차단 |
| `unit-test` | `./mvnw -B test` | 아니오 | 실패 시 PR 머지 차단 |
| `integration-test` | `./mvnw -B -Pit -Dgroups=integration test` | 예 | 별도 잡, 실패 시 PR 머지 차단 |

- `unit-test`는 일반 JDK 17 러너로 충분하다.
- `integration-test`는 Docker-in-Docker 또는 호스트 Docker 소켓 마운트가 가능한 러너에서 실행한다.
- Testcontainers Reuse는 사용하지 않고 매 실행 새 컨테이너로 격리한다.
- Maven 로컬 저장소(`~/.m2/repository`) 캐시를 적용하고, `postgres:16` 이미지는 러너 워밍업 단계에서 미리 pull하는 것을 권장한다.
- 모든 PR은 `build`와 `unit-test`를 필수로 하고, main/master 머지 직전에는 `integration-test`까지 필수로 둔다.
- 야간 잡은 추후 maven-failsafe 도입 시 `./mvnw -Pit verify` 기준으로 확장한다.
