# M3 진입점검 및 M2 매퍼 보완 지시서

## 관리자 보고 - M3 진입 점검 결과

### 결론

M3 챗봇 런타임은 M2 미커밋 구현물 기준으로 M3 설계지시서 진입 전제 일부가 부족했다. 매퍼 4개에 SELECT 6개와 DTO 1개를 보완해 M3 런타임 구현 진입에 필요한 조회 기반을 마련한다.

### 진입 전제 충족 매트릭스

| # | 진입 전제 | 상태 |
|---|---|---|
| 1 | Flyway V1~V3 적용 | 충족 |
| 2 | scenario_* 테이블 6개 정의 | 충족 |
| 3 | findPublishedByScenarioId | 충족 |
| 4 | ScenarioMatchingCacheInvalidator 인터페이스/Noop | 충족 |
| 5 | Caffeine 3.1.8 의존성 | 충족 |
| 6 | 현재 노드 enabled=true 옵션 조회 | 보완 대상 |
| 7 | 시나리오 enabled=true 키워드 조회 | 보완 대상 |
| 8 | 시나리오 단위 enabled=true 유사어 조회 | 보완 대상 |
| 9 | 전체 active 시나리오 keyword/synonym 일괄 조회 | 보완 대상 |
| 10 | 운영 DB pgcrypto 확장 권한 | DBA 확인 필요 |

### 보완 범위

- `ScenarioNodeOptionMapper.findEnabledByNodeId(nodeId)` 추가
- `ScenarioKeywordMapper.findEnabledByScenarioId(scenarioId)` 추가
- `ScenarioSynonymRow(scenarioId, keywordId, synonym, weight)` DTO 추가
- `ScenarioSynonymMapper.findEnabledByScenarioId(scenarioId)` 추가
- `ScenarioMapper.findActiveForMatching()` 추가
- `ScenarioKeywordMapper.findEnabledForActiveScenarios()` 추가
- `ScenarioSynonymMapper.findEnabledForActiveScenarios()` 추가

DB 변경과 Flyway 신규 마이그레이션은 포함하지 않는다.

### 정책

- active 매칭 대상은 `scenario.status = 'ACTIVE'`, `active_version_id IS NOT NULL`, 직속 `scenario_category.enabled = TRUE` 조건으로 제한한다.
- 카테고리 상위 트리 비활성화 cascade는 이번 보완 범위에서 제외하고 후속 결정사항으로 둔다.
- 키워드/유사어 일괄 조회는 active 시나리오 조건과 각 행의 `enabled = TRUE`를 함께 적용해 M3 매칭 캐시 구성 시 N+1 조회를 피할 수 있게 한다.

### 남은 결정사항

1. 상위 카테고리 비활성화 시 하위 시나리오를 매칭에서 제외할지 결정해야 한다.
2. 운영 DB에서 `pgcrypto` 확장 생성 권한을 확인해야 한다. 권한이 없으면 M3 `chat_session.id` 생성 전략을 애플리케이션 UUID 생성으로 대체한다.
3. M3 점수식 구현 시 `weight / 100` 정수 나눗셈을 피하고 `double` 또는 `BigDecimal` 기반 계산을 적용한다.
