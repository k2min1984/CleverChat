> 작성일: 2026-05-08  
> 대상 프로젝트: `3.개발/cleverchat`

## 0. 진입 전제

M3는 M2 시나리오 도메인의 런타임 참조 기능이다. 구현 진입 전 아래 조건을 먼저 확인한다.

| 항목 | 기준 |
|---|---|
| 선행 마이그레이션 | Flyway `V1`, `V2`, `V3__scenario_baseline.sql`이 순서대로 적용되어야 한다. |
| 선행 코드 | `scenario`, `scenario_version`, `scenario_node`, `scenario_node_option`, `scenario_keyword`, `scenario_synonym` 조회가 가능해야 한다. |
| 게시 버전 | 신규 챗봇 세션은 최신 `PUBLISHED` 버전만 시작한다. 게시 버전이 없으면 `SCENARIO_ACTIVE_VERSION_REQUIRED`를 반환한다. |
| 권한 | 사용자 `/chat/**`는 비로그인 접근 가능, 관리자 `/admin/api/chat/**`는 `ADMIN`, `OPERATOR`만 허용한다. |
| 보안 | 익명 사용자도 CSRF 토큰을 받아 상태 변경 API에 제출해야 한다. |

M2 코드가 아직 없거나 V3가 미적용이면 M3 구현을 시작하지 않는다. 이 경우 M2 구현 또는 마이그레이션을 먼저 완료한다.

### 0.1 설계 검수 결과

| 영역 | 결론 | 구현 지시 |
|---|---|---|
| 데이터 모델 | V4 baseline으로 구현 가능. `chat_failure.review_comment`는 ERD, SQL, model, mapper에 모두 포함한다. | Flyway 작성 후 Testcontainers PostgreSQL에서 V1~V4 순차 적용을 먼저 검증한다. |
| M2 의존성 | 게시 버전, 시작 노드, enabled 옵션/키워드 조회가 M3의 선행 블로커다. | M2 조회 mapper가 없으면 M3에서 임시 SQL을 중복 작성하지 말고 M2 mapper를 먼저 보강한다. |
| 보안 | 고위험 PII는 차단, 이메일/전화번호는 마스킹으로 확정한다. | `PiiGuard`를 메시지 저장 전 서비스 입구에서 강제하고 로그 필터와 failure detail에도 동일 정책을 적용한다. |
| 동시성 | 동일 세션 진행 요청은 DB lock 기반 직렬화가 필요하다. | `pg_advisory_xact_lock(hashtext('chat_session:' || session_id::text))`로 단일화하고 `SELECT ... FOR UPDATE` 방식과 혼용하지 않는다. |
| 테스트 | 단위/통합/보안 회귀 케이스가 분리되어 있다. | 구현 PR은 `mvn test` 외에 Flyway 적용, 민감정보 로그 검색, 360/768/1280px 화면 확인 결과를 남긴다. |
| 운영 | 만료/파기/실패 큐/SLO 후보가 운영 문서에 정의되어 있다. | 배치 로그는 건수, 기간, 소요 시간만 남기고 원문 입력과 식별자 원문을 제외한다. |

### 0.2 구현 제외 범위

- M4 검색 랭킹, 전문 검색 인덱스, 외부 검색 API 호출
- M5 크롤링/수집 데이터 연동
- M6 통계 대시보드, 알림 채널, 추천 질문 사용량 가중치
- 챗봇 임베드 위젯과 외부 도메인 CORS/frame 허용
- 조건식 DSL 실행과 복잡한 분기 평가

## 1. 결정값 보강

| # | 항목 | 결정 |
|---|---|---|
| 1 | UUID 생성 | PostgreSQL `gen_random_uuid()` 사용. V4 첫 줄에 `CREATE EXTENSION IF NOT EXISTS pgcrypto;`를 둔다. |
| 2 | 익명 사용자 식별 | `anonymous_id` 쿠키 UUID, 만료 1년, `HttpOnly=true`, `Secure=true`, `SameSite=Lax`. |
| 3 | IP/UA 저장 | 원문 저장 금지. `SHA-256(serverSalt + value)` 해시만 저장한다. |
| 4 | 세션 만료 | 마지막 활동 후 30분. 만료 배치는 5분 주기, 1회 1,000건 기본값. |
| 5 | 대화 보존 | 세션, 메시지, 피드백, 실패 기록은 90일 후 파기한다. |
| 6 | 자유 텍스트 제한 | 1~500자. 사용자 입력 원문은 감사 로그에 저장하지 않는다. |
| 7 | 피드백 코멘트 제한 | 0~1,000자. HTML 입력은 거절하고 화면 출력은 escape한다. |
| 8 | PII 처리 | 주민등록번호와 카드번호는 차단, 이메일과 전화번호는 저장 전 마스킹한다. |
| 9 | Rate limit | 단일 인스턴스 `ConcurrentMap` 구현체(`ConcurrentHashMap`) 기반 토큰버킷. 익명 사용자 기준 분당 30건 기본값. 멀티 인스턴스 저장소는 M3에서 결정하지 않고 별도 설계로 확정한다. |
| 10 | 동시성 | 동일 세션 진행 요청은 `pg_advisory_xact_lock(hashtext('chat_session:' || session_id::text))`로 직렬화한다. |
| 11 | 매칭 캐시 | 시나리오 키워드/유사어 애플리케이션 캐시 TTL 기본값은 300초다. M2 게시/키워드 저장 성공 후 캐시 무효화 훅을 호출한다. |
| 12 | 감사 로그 | 비로그인 사용자 채팅 행위는 감사 대상에서 제외하고 운영 로그와 런타임 테이블로 추적한다. 관리자 실패 검토만 감사 로그 대상이다. |
| 13 | 추천 질문 관리 | M3에서 관리자 CRUD를 포함한다. 추천 질문은 캐시를 사용하지 않고 매 요청 DB 조회로 처리한다. 카테고리 비활성화 시 연결 시나리오의 추천 질문은 사용자 응답에서 제외한다. 사용량 가중치와 자동 추천은 M6로 이관한다. |
| 14 | fallback | M4 검색은 인터페이스 stub만 둔다. M3는 키워드 검색 결과 카드 또는 `CHAT_NO_MATCH`만 처리한다. |
| 15 | 프록시 헤더 | `server.forward-headers-strategy=framework`를 전제로 한다. prod 프로파일에서만 `X-Forwarded-For` 누락 등 부팅 경고를 남긴다. |

## 2. Flyway V4

파일: `3.개발/cleverchat/src/main/resources/db/migration/V4__chat_runtime_baseline.sql`

```sql
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE chat_session (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    anonymous_id UUID NOT NULL,
    user_id BIGINT NULL,
    scenario_id BIGINT NOT NULL,
    version_id BIGINT NOT NULL,
    current_node_id BIGINT NULL,
    state VARCHAR(20) NOT NULL,
    started_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    last_activity_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    expires_at TIMESTAMPTZ NOT NULL,
    ip_hash VARCHAR(64) NOT NULL,
    user_agent_hash VARCHAR(64) NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_chat_session_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    CONSTRAINT fk_chat_session_scenario FOREIGN KEY (scenario_id) REFERENCES scenario(id),
    CONSTRAINT fk_chat_session_version FOREIGN KEY (version_id) REFERENCES scenario_version(id),
    CONSTRAINT fk_chat_session_current_node FOREIGN KEY (current_node_id) REFERENCES scenario_node(id),
    CONSTRAINT ck_chat_session_state CHECK (state IN ('ACTIVE', 'COMPLETED', 'ABANDONED', 'EXPIRED'))
);

CREATE INDEX ix_chat_session_anonymous_started
    ON chat_session (anonymous_id, started_at DESC);

CREATE INDEX ix_chat_session_state_expires
    ON chat_session (state, expires_at);

CREATE TABLE chat_message (
    id BIGSERIAL PRIMARY KEY,
    session_id UUID NOT NULL,
    seq INTEGER NOT NULL,
    direction VARCHAR(10) NOT NULL,
    node_id BIGINT NULL,
    option_id BIGINT NULL,
    content TEXT NOT NULL,
    payload JSONB NULL,
    latency_ms INTEGER NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_chat_message_session FOREIGN KEY (session_id) REFERENCES chat_session(id) ON DELETE CASCADE,
    CONSTRAINT fk_chat_message_node FOREIGN KEY (node_id) REFERENCES scenario_node(id) ON DELETE SET NULL,
    CONSTRAINT fk_chat_message_option FOREIGN KEY (option_id) REFERENCES scenario_node_option(id) ON DELETE SET NULL,
    CONSTRAINT ux_chat_message_session_seq UNIQUE (session_id, seq),
    CONSTRAINT ck_chat_message_direction CHECK (direction IN ('USER', 'BOT', 'SYSTEM'))
);

CREATE INDEX ix_chat_message_session_created
    ON chat_message (session_id, created_at, id);

CREATE TABLE chat_feedback (
    id BIGSERIAL PRIMARY KEY,
    message_id BIGINT NOT NULL,
    rating VARCHAR(10) NOT NULL,
    comment TEXT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    ip_hash VARCHAR(64) NOT NULL,
    CONSTRAINT fk_chat_feedback_message FOREIGN KEY (message_id) REFERENCES chat_message(id) ON DELETE CASCADE,
    CONSTRAINT ux_chat_feedback_message UNIQUE (message_id),
    CONSTRAINT ck_chat_feedback_rating CHECK (rating IN ('UP', 'DOWN'))
);

CREATE INDEX ix_chat_feedback_rating_created
    ON chat_feedback (rating, created_at DESC);

CREATE TABLE chat_failure (
    id BIGSERIAL PRIMARY KEY,
    session_id UUID NOT NULL,
    message_id BIGINT NULL,
    reason VARCHAR(30) NOT NULL,
    detail JSONB NULL,
    reviewed BOOLEAN NOT NULL DEFAULT false,
    reviewed_by BIGINT NULL,
    reviewed_at TIMESTAMPTZ NULL,
    review_comment TEXT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_chat_failure_session FOREIGN KEY (session_id) REFERENCES chat_session(id) ON DELETE CASCADE,
    CONSTRAINT fk_chat_failure_message FOREIGN KEY (message_id) REFERENCES chat_message(id) ON DELETE SET NULL,
    CONSTRAINT fk_chat_failure_reviewer FOREIGN KEY (reviewed_by) REFERENCES users(id) ON DELETE SET NULL,
    CONSTRAINT ck_chat_failure_reason CHECK (reason IN ('NO_MATCH', 'EXPIRED', 'INVALID_OPTION', 'SYSTEM_ERROR', 'PII_BLOCKED', 'RATE_LIMITED'))
);

CREATE INDEX ix_chat_failure_reviewed_created
    ON chat_failure (reviewed, created_at DESC);

CREATE TABLE chat_recommendation (
    id BIGSERIAL PRIMARY KEY,
    scenario_id BIGINT NOT NULL,
    label VARCHAR(200) NOT NULL,
    priority INTEGER NOT NULL DEFAULT 100,
    enabled BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_chat_recommendation_scenario FOREIGN KEY (scenario_id) REFERENCES scenario(id) ON DELETE CASCADE
);

CREATE INDEX ix_chat_recommendation_enabled_priority
    ON chat_recommendation (enabled, priority, id);

CREATE INDEX ix_chat_recommendation_scenario
    ON chat_recommendation (scenario_id);
```

서비스 검증으로 보장할 제약:

- `chat_session.scenario_id`, `version_id`는 생성 후 변경하지 않는다.
- `version_id`는 세션 시작 당시 해당 시나리오의 `PUBLISHED` 버전이어야 한다.
- `current_node_id`, `chat_message.node_id`, `chat_message.option_id`는 같은 `version_id`의 노드/옵션이어야 한다.
- `chat_feedback.message_id`는 `BOT` 메시지만 허용한다.

## 4. 자유 텍스트 매칭 알고리즘

### 4.1 정규화

입력과 비교 대상 문자열에 동일한 정규화를 적용한다.

1. 앞뒤 공백 제거
2. Unicode NFKC 정규화
3. 영문 소문자 변환
4. HTML 태그, 제어문자 제거 또는 거절
5. 연속 공백 1칸으로 축약
6. 한글/영문/숫자/공백 외 기호는 비교용 문자열에서 제거

저장되는 사용자 메시지는 PII 정책을 거친 마스킹 텍스트이고, 매칭용 정규화 문자열은 DB에 저장하지 않는다.

### 4.2 PII 선처리

| 유형 | 정규식/규칙 | 처리 |
|---|---|---|
| 주민등록번호 | `\b\d{6}[- ]?[1-4]\d{6}\b` | 저장 전 차단, `CHAT_PII_BLOCKED` |
| 카드번호 | 13~19자리 숫자 후보 + Luhn 통과 | 저장 전 차단, `CHAT_PII_BLOCKED` |
| 이메일 | `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` | local 앞 2자 외 `*` 마스킹 |
| 전화번호 | `01[016789][- ]?\d{3,4}[- ]?\d{4}` 및 `0\d{1,2}[- ]?\d{3,4}[- ]?\d{4}` | 중간 자리 마스킹 |

차단 시 사용자 메시지를 저장하지 않고 `chat_failure.reason='PII_BLOCKED'`를 기록한다. `detail`에는 PII 원문 없이 탐지 유형과 길이만 남긴다.

### 4.3 매칭 단계

1. 현재 노드 enabled 옵션의 `label` exact match
2. 현재 노드 enabled 옵션의 `label` contains match
3. 현재 시나리오의 enabled keyword/synonym match
4. 전체 active 시나리오의 enabled keyword/synonym match
5. `FallbackSearchService` stub 호출
6. 결과 없음이면 `CHAT_NO_MATCH`

### 4.4 점수식

M3 점수는 단순 가중치로 고정한다.

| 조건 | 점수 |
|---|---:|
| 현재 옵션 exact | 100 |
| 현재 옵션 contains | 85 |
| 현재 시나리오 keyword exact | `80 * weight / 100` |
| 현재 시나리오 synonym exact | `70 * weight / 100` |
| 전체 시나리오 keyword exact | `60 * weight / 100` |
| 전체 시나리오 synonym exact | `50 * weight / 100` |

임계값은 50점이다. 동일 점수는 현재 시나리오, 높은 weight, 낮은 sort/priority, 낮은 id 순으로 결정한다. 임계값 미만이면 fallback으로 보낸다.

### 4.5 캐시 무효화

키워드/유사어 캐시를 둘 경우 아래 이벤트 후 무효화한다.

- 시나리오 게시 성공
- 시나리오 상태 `ACTIVE`/`INACTIVE` 변경
- 키워드/유사어 저장 성공
- 카테고리 비활성화처럼 다수 시나리오 매칭에 영향을 주는 변경

M2는 아래 인터페이스와 기본 구현을 먼저 제공한다.

```java
package kr.co.cleverchat.domain.scenario.event;

public interface ScenarioMatchingCacheInvalidator {
    void onScenarioChanged(long scenarioId);
    void onGlobalKeywordChanged();
}
```

기본 구현은 `NoopScenarioMatchingCacheInvalidator`다. M3 구현 시 `ChatMatchingCacheInvalidator`로 교체하고 `onScenarioChanged`는 해당 시나리오 캐시, `onGlobalKeywordChanged`는 전역 키워드/카테고리 영향 캐시를 무효화한다. 카테고리 비활성화 저장 성공 지점에서는 영향 시나리오별 `onScenarioChanged(scenarioId)` 또는 전역 영향이면 `onGlobalKeywordChanged()`를 호출한다. 기본 TTL은 300초다.

추천 질문은 캐시를 사용하지 않는다. 따라서 추천 질문 자체에는 무효화 호출이 없고, 사용자 `GET /chat/api/recommendations`는 매 요청 `chat_recommendation.enabled=true`, 시나리오 활성, 카테고리 활성 조건으로 DB에서 조회한다. 카테고리 비활성화 저장 성공 직후부터 연결 추천 질문은 사용자 응답에서 제외되어야 한다.

## 5. 검증, 동시성, 트랜잭션, 감사

### 5.1 API 검증

| API | 핵심 검증 |
|---|---|
| `POST /chat/api/sessions` | `scenarioId` 양수, active scenario, 최신 `PUBLISHED` 버전, start node 존재 |
| `GET /chat/api/sessions/{id}` | 본인 세션, 만료 상태, 응답 원문 노출 제한 |
| `POST /chat/api/sessions/{id}/select-option` | 본인 세션, `ACTIVE`, 현재 노드 옵션, enabled option |
| `POST /chat/api/sessions/{id}/free-text` | 본인 세션, `ACTIVE`, 1~500자, PII 처리, rate limit |
| `GET /chat/api/history` | `anonymous_id` 본인 이력, page/size 상한, state allow-list, 90일 범위 제한 |
| `POST /chat/api/messages/{messageId}/feedback` | 본인 세션의 `BOT` 메시지, 중복 피드백 없음, comment 1,000자 이하 |
| 관리자 API | `ADMIN`/`OPERATOR`, page size 상한, 원문 식별자 미노출 |

### 5.2 동시성

동일 세션 진행 요청은 단일 트랜잭션에서 다음 순서로 처리한다.

```sql
select pg_advisory_xact_lock(hashtext('chat_session:' || #{sessionId}));
```

`ChatRuntimeService`의 진행성 API 진입 직후, 세션 조회와 seq 계산 전에 lock을 획득한다.

```java
@Transactional
public ChatProgressResult selectOption(UUID sessionId, long optionId, ChatRequestContext context) {
    chatSessionMapper.lockSessionByAdvisoryKey(sessionId);

    ChatSession session = chatSessionMapper.findById(sessionId)
            .orElseThrow(() -> new ChatException(CHAT_SESSION_NOT_FOUND));
    validateOwnerAndActive(session, context);

    int nextSeq = chatMessageMapper.selectNextSeq(sessionId);
    // 사용자 메시지 저장, 다음 노드 계산, 봇 메시지 저장, 세션 갱신
}
```

1. lock 획득
2. `chat_session` 재조회
3. 상태와 현재 노드 재검증
4. `max(seq)+1` 계산
5. 사용자 메시지 저장
6. 봇 메시지 또는 실패 기록 저장
7. 세션 상태, 현재 노드, 만료 시각 갱신

`(session_id, seq)` UNIQUE 충돌은 409 `STATE_CONFLICT`로 변환한다.

### 5.3 트랜잭션 경계

| 작업 | 범위 |
|---|---|
| 세션 시작 | 세션 생성 + 시작 봇 메시지 저장 |
| 옵션 선택 | lock + 사용자 메시지 + 봇 메시지 + 세션 갱신 |
| 자유 텍스트 | rate limit + PII 검사 + lock + 메시지/매칭/failure + 세션 갱신 |
| 사용자 종료 | lock + `ABANDONED` 갱신 + 시스템 메시지 후보 저장 |
| 피드백 | 본인 검증 + UNIQUE 확인 + 저장 |
| 실패 검토 | 관리자 권한 + reviewed 갱신 + 감사 로그 |
| 만료 배치 | chunk 단위 상태 갱신 |
| 파기 배치 | FK 순서에 따른 chunk 삭제 |

### 5.4 감사와 운영 로그

- 비로그인 사용자 채팅, free-text, feedback은 감사 로그에 남기지 않는다.
- 관리자 실패 검토는 `CHAT_FAILURE_REVIEW` 이벤트로 감사 로그를 남긴다.
- 운영 로그에는 원문 사용자 입력 대신 마스킹 요약 100자 이하만 남긴다.
- 쿠키, CSRF 토큰, anonymous_id 원문, IP 원문, User-Agent 원문은 로그 금지다.

## 14. 인수 기준

- [ ] V4가 깨끗한 PostgreSQL DB에서 V1~V4 순서로 적용된다.
- [ ] 비로그인 사용자가 `/chat`에서 CSRF 토큰과 `anonymous_id` 쿠키를 받고 세션을 시작할 수 있다.
- [ ] 옵션 선택, 자유 텍스트 매칭, fallback, NO_MATCH가 API 문서와 같은 응답 구조를 사용한다.
- [ ] `GET /chat/api/history`가 90일 본인 이력만 반환하고 원문 식별자를 노출하지 않는다.
- [ ] 주민번호/카드번호 입력은 저장되지 않고 `CHAT_PII_BLOCKED`로 차단된다.
- [ ] rate limit 초과는 429와 `RATE_LIMIT_EXCEEDED`로 반환된다.
- [ ] 만료 세션 접근은 410과 `CHAT_SESSION_EXPIRED`로 통일된다.
- [ ] 관리자 화면에서 실패 큐 검토와 추천 질문 CRUD가 가능하다.
- [ ] 원문 IP, UA, anonymous_id, CSRF token, PII가 로그와 관리자 응답에 노출되지 않는다.
- [ ] 만료 배치와 90일 파기 배치가 chunk 단위로 동작한다.
- [ ] `mvn test`가 통과한다.

## 15. M4 Stub

M4 검색 연동 전까지 아래 인터페이스와 기본 구현을 둔다.

```java
public interface FallbackSearchService {
    FallbackSearchResult search(String text, Long currentScenarioId, UUID sessionId);
}
```

`NoopFallbackSearchService`는 빈 결과를 반환한다. 검색 결과가 비어 있으면 `chat_failure.reason='NO_MATCH'`를 남기고 `CHAT_NO_MATCH` 또는 안내 메시지를 반환한다. 실제 검색 인덱스, 외부 호출, 랭킹은 M4에서 구현한다.
