## 2. Codex 다음 작업 결정 - M2 구현 진입

Codex의 다음 주 작업은 M2 구현이다.

기준 문서는 `M2_시나리오_상세작업지시서.md`를 최상위 구현 지시로 둔다. 본 문서는 그 지시서에 빠지거나 더 명확히 고정해야 하는 항목을 보완한다.

구현 순서는 다음을 따른다.

1. DB 마이그레이션은 `V3__scenario_baseline.sql`과 `V3_1__auth_must_change_password.sql`로 분리하고, 공통 응답/예외 기반을 먼저 구현한다.
2. SecurityConfig 보완, OPERATOR 비활성 시딩과 최초 비밀번호 변경 강제, 관리자 API JSON 오류 응답을 연결한다.
3. scenario 도메인 model/mapper/service/API를 추가한다.
4. 그래프 검증, 게시 상태 전이, 키워드 replace 저장, 감사 기록을 구현한다.
5. Thymeleaf 관리자 화면은 목록/등록/상세/미리보기의 최소 운영 흐름을 우선 완성한다.
6. 단위 테스트와 Testcontainers 통합 테스트로 DB 제약, 상태 전이, 권한, 감사 기록을 검증한다.

대규모 그래프 시각 편집기, 챗봇 런타임 위젯 재사용, 검색 랭킹 고도화는 M2 범위에서 제외한다.

## 3. M2 구현 보완 체크리스트 17개

| # | 항목 | 지시 | 수용 기준 |
|---|---|---|---|
| 1 | 응답 DTO 표준화 | `ApiResponse<T>`, `PageResponse<T>`를 먼저 추가하고 `/admin/api/**`는 동일 형식으로 반환한다. | 성공/실패/페이징 응답 구조가 API별로 갈라지지 않는다. |
| 2 | 페이징 정책 | 목록 API는 `page`, `size`, `keyword`, `status`, `categoryId`를 기본 쿼리로 받는다. `size`는 서버에서 상한을 둔다. | 무제한 목록 조회가 발생하지 않는다. |
| 3 | REST CSRF | `CookieCsrfTokenRepository.withHttpOnlyFalse()`를 적용하고 AJAX 호출에서 CSRF 헤더를 보낼 수 있게 한다. | POST/PUT/DELETE가 CSRF 검증을 통과하고 누락 시 403 JSON을 반환한다. |
| 4 | API 인증/권한 오류 | `/admin/api/**` 미인증은 401 JSON, 권한 부족은 403 JSON으로 반환한다. | HTML 로그인 페이지가 API 응답으로 섞이지 않는다. |
| 5 | metadata XSS | `scenario_node.metadata`는 JSON으로 저장하되 화면 출력 시 escape를 기본으로 한다. HTML 렌더링 허용 필드는 두지 않는다. | metadata에 스크립트 문자열이 있어도 화면에서 실행되지 않는다. |
| 6 | OPERATOR 시드 | 운영 기본 OPERATOR 계정은 비활성 상태로 생성하고 `must_change_password=true`로 둔다. `users.must_change_password`는 V3.1에서 분리 추가한다. | 기본 계정이 즉시 권한을 행사하지 못하고, 활성화 후에도 임시 비밀번호 사용이 차단된다. |
| 7 | layout fragment | 관리자 화면 공통 레이아웃과 메뉴 fragment를 재사용한다. 기존 관리자 홈 링크 체계를 깨지 않는다. | `/admin/scenarios` 진입 링크가 관리자 화면에 노출된다. |
| 8 | 메시지 번들 | 화면 문구와 검증 메시지는 가능하면 `messages*.properties`로 분리한다. | 하드코딩 문구가 과도하게 늘지 않는다. |
| 9 | M1 회귀 | 로그인, 세션 만료, 로그인 실패 잠금, ADMIN 관리자 홈 접근을 회귀 테스트한다. | M2 보안 설정 변경으로 M1 기능이 깨지지 않는다. |
| 10 | 예외 매핑 | `VALIDATION_ERROR`, `NOT_FOUND`, `STATE_CONFLICT`, `DUPLICATE_RESOURCE`, `ACCESS_DENIED`를 공통 매핑한다. | 상태 충돌과 검증 실패가 모두 400으로 뭉개지지 않는다. |
| 11 | 감사 마스킹 | 감사 detail에는 비밀번호, 세션 ID, CSRF 토큰, API 키, 과도한 본문을 저장하지 않는다. | 감사 로그가 추적 가능하되 민감정보를 포함하지 않는다. |
| 12 | 트랜잭션 롤백 | 그래프 저장과 키워드/유사어 저장은 단일 트랜잭션 replace 방식으로 처리한다. | 중간 실패 시 이전 데이터가 유지된다. |
| 13 | 게시 불변성 | `PUBLISHED`, `ARCHIVED` 버전 직접 수정은 `STATE_CONFLICT`로 차단한다. | 게시된 버전은 복제 후 새 초안으로만 변경 가능하다. |
| 14 | 쿠키 보안 속성 | 세션성 식별 쿠키는 `SameSite=Lax`, `Secure=true`, `HttpOnly=true`를 기본값으로 한다. | 운영 HTTPS 전제에서 쿠키 탈취/교차 사이트 전송 위험을 낮춘다. |
| 15 | CSRF 쿠키 예외 | CSRF 토큰 쿠키는 AJAX 헤더 전송을 위해 `HttpOnly=false`로 둔다. `Secure=true`, `SameSite=Lax`는 동일 적용한다. | 보안 속성 기준과 프론트 CSRF 처리가 충돌하지 않는다. |
| 16 | 프록시 헤더 | `server.forward-headers-strategy=framework`를 설정하고, prod 프로파일에서만 부팅 경고 로그를 출력한다. | nginx HTTPS 종단 환경에서 scheme/client IP 인식이 일관된다. |
| 17 | 매칭 캐시 TTL | M3 키워드/유사어 매칭 캐시 기본 TTL은 300초로 문서화하고 yml 후보 키에 반영한다. | 캐시 무효화 훅 누락 시에도 짧은 TTL로 정합성 회복 경로를 둔다. |

## 4. M2 PR 머지 직전 추가 수용 기준

- Flyway V1~V3.1이 PostgreSQL 16 기준 clean schema에서 성공한다.
- `mvn test`가 성공한다.
- ADMIN과 OPERATOR 모두 `/admin/scenarios` 화면에 접근할 수 있다.
- USER 또는 익명 사용자는 관리자 시나리오 화면과 API에 접근할 수 없다.
- `/admin/api/**`의 400/401/403/404/409 응답은 공통 JSON 형식을 따른다.
- 시나리오당 `PUBLISHED` 버전은 동시에 1개만 존재한다.
- 게시 시 기존 `PUBLISHED` 버전은 `ARCHIVED`로 전환된다.
- 시작 노드 누락, 없는 다음 노드, 도달 불가능 노드가 있는 그래프는 게시할 수 없다.
- `END` 노드는 옵션을 가질 수 없다.
- 키워드/유사어 일괄 저장 실패 시 이전 데이터가 남아 있다.
- 생성/수정/삭제/그래프 저장/게시/활성화/비활성화/키워드 저장 감사 로그가 남는다.
- metadata와 본문 출력은 Thymeleaf escape를 기본으로 한다.
- M1 로그인 성공/실패/잠금/세션 정책 회귀 확인 결과를 PR 설명에 포함한다.

## 8. 영향 범위 요약

| 범위 | 변경 유형 | 영향 |
|---|---|---|
| DB | Flyway V3 신규 테이블/인덱스/FK, V3.1 `users.must_change_password` | V3는 기존 인증 테이블을 건드리지 않고, 인증 보완은 V3.1로 분리한다. |
| 보안 | `/admin/**` 권한 확장, API JSON 오류, CSRF 쿠키 토큰 | M1 로그인/인가 회귀 확인이 필요하다. |
| 운영 계정 | OPERATOR 비활성 시딩, `must_change_password=true` | `users.must_change_password` 컬럼은 V3.1에서 추가하고 임시 비밀번호 운영 절차가 필요하다. |
| 인프라 | `forward-headers-strategy=framework`, prod 전용 부팅 경고 | nginx 헤더 설정과 운영 로그 확인 절차가 필요하다. |
| 캐시 | M3 매칭 캐시 TTL 300초 | 게시/키워드 저장 후 무효화 훅 또는 TTL 정합성 확인이 필요하다. |
| 도메인 | scenario 패키지 신규 구현 | 기존 admin/auth 도메인과 낮은 결합을 유지한다. |
| 화면 | 관리자 시나리오 화면 추가 | 기존 관리자 홈 메뉴에 링크 추가가 필요하다. |
| 감사 | 직접 기록용 recorder 추가 | 기존 `@Audited` AOP는 제거하지 않는다. |
| 테스트 | 단위/통합/보안 회귀 추가 | Testcontainers 실행 환경이 필요하다. |
| 배포 | V3 + V3.1 마이그레이션 포함 | 운영 롤백은 백업 복구 기준으로 판단하되, 데이터 생성 전이면 V3.1 단독 롤백 가능성을 DBA와 검토한다. |
