# M2 테스트 분리 정책 작업지시서

> 작성일: 2026-05-12
> 대상 마일스톤: M2 시나리오 도메인
> 범위: 문서 정합화. `pom.xml`의 Surefire 그룹 분리와 테스트 코드의 `@Tag("integration")` 구성은 변경하지 않는다.

## 1. 배경

Windows 환경 기준 실측 결과는 다음과 같다.

| 항목 | 결과 | 비고 |
|---|---|---|
| `mvnw.cmd test-compile` | 정상 완료 | 한글 경로/CP949 환경에서 컴파일 정상 |
| `mvnw.cmd test` | 정상 통과 | `@Tag("integration")` 제외, 순수 단위 테스트만 실행 |
| Testcontainers 통합 테스트 | Docker Desktop 미기동 시 실패 재현 | Docker daemon 미연결로 컨테이너 생성 실패 |

따라서 기본 개발 루프와 PIT(Testcontainers 통합 테스트) 실행 정책을 분리한다. Docker Desktop이 없는 개발자도 `mvn test` 기준 단위 테스트를 실행할 수 있어야 하며, Testcontainers 통합 테스트는 명시적으로 `-Pit` 또는 `integration` 그룹을 지정할 때만 실행한다.

## 2. 테스트 분리 정책

PIT는 Persistence/Integration Test의 내부 명칭이며, mutation testing 도구 PIT를 의미하지 않는다. 문서에서는 혼동 방지를 위해 "PIT(Testcontainers 통합 테스트)"로 표기한다.

| 구분 | 위치 | JUnit 5 태그 | 외부 의존 | 기본 `mvn test` 포함 여부 |
|---|---|---|---|---|
| 순수 단위 테스트 | `src/test/java` | 태그 없음 | 없음 | 포함 |
| Spring Boot 슬라이스 테스트 | `src/test/java` | 태그 없음 | 없음 | 포함 |
| PIT(Testcontainers 통합 테스트) | `src/test/java` | `@Tag("integration")` 필수 | Docker daemon, PostgreSQL 16 이미지 | 제외 |
| 풀 컨텍스트 `@SpringBootTest` + 실 DB | `src/test/java` | `@Tag("integration")` 필수 | Docker daemon | 제외 |

`pom.xml`의 현재 분리 구성은 유지한다.

```xml
<properties>
    <test.excluded.groups>integration</test.excluded.groups>
</properties>
...
<configuration>
    <excludedGroups>${test.excluded.groups}</excludedGroups>
</configuration>
...
<profile>
    <id>it</id>
    <properties>
        <test.excluded.groups/>
    </properties>
</profile>
```

## 3. 실행 명령어

Windows PowerShell 기준 작업 디렉토리는 `C:\02.Project\02.자바\01.WorkSpace\CLEVERCHAT\3.개발\cleverchat`이다.

```powershell
# 단위 테스트만, Docker 불필요
.\mvnw.cmd test

# 컴파일만 확인
.\mvnw.cmd test-compile

# 통합 테스트 포함, Docker Desktop 필수
docker info
.\mvnw.cmd -Pit test

# 통합 테스트만 단독 실행
.\mvnw.cmd -Pit -Dgroups=integration test
```

macOS/Linux 동등 명령은 다음과 같다.

```bash
./mvnw test
./mvnw test-compile
./mvnw -Pit test
./mvnw -Pit -Dgroups=integration test
```

## 4. Docker Desktop 조건과 실패 원인

| 조건 | 기준 |
|---|---|
| Docker Desktop | Windows 기준 4.x 이상, WSL2 백엔드 권장 |
| Docker daemon | `docker info`가 오류 없이 응답 |
| 이미지 | `postgres:16` pull 가능 |
| 포트 | Testcontainers 임시 포트 사용 가능 |

| 환경 상태 | 예상 실패 | 원인 |
|---|---|---|
| Docker Desktop 미설치 | `Could not find a valid Docker environment` | Testcontainers가 데몬 소켓을 찾지 못함 |
| Docker Desktop 미기동 | `Cannot connect to the Docker daemon at npipe:////./pipe/docker_engine` | 데몬 프로세스 미실행 |
| 이미지 수신 불가 | `pull access denied`, `i/o timeout` | 사설망/프록시/미러 미설정 |
| WSL2 백엔드 문제 | 컨테이너 생성 hang 또는 시간 초과 | WSL2 통합 비활성 또는 리소스 부족 |

진단 순서는 `docker info`, `docker run --rm hello-world`, `docker pull postgres:16`이다. 세 단계가 모두 정상인데도 실패하면 코드 결함으로 보고 결함 티켓을 등록한다.

## 5. CI 실행 전략

| 단계 | 명령 | Docker 필요 | 실패 처리 |
|---|---|---|---|
| `build` | `./mvnw -B -DskipTests package` | 아니오 | 즉시 실패 |
| `unit-test` | `./mvnw -B test` | 아니오 | PR 머지 차단 |
| `integration-test` | `./mvnw -B -Pit -Dgroups=integration test` | 예 | 별도 잡, PR 머지 차단 |

- `unit-test`는 JDK 17 러너만 있으면 실행 가능하다.
- `integration-test`는 Docker-in-Docker 또는 호스트 Docker 소켓 마운트가 가능한 러너에서 실행한다.
- Testcontainers Reuse는 사용하지 않고 매 실행 새 컨테이너로 격리한다.
- Maven 로컬 저장소 캐시와 `postgres:16` 사전 pull을 권장한다.
