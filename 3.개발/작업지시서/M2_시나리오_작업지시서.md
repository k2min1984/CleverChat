> 작성일: 2026-05-08

## 1. 목표

시나리오 관리의 최소 기능을 구현한다.

- 카테고리 목록/저장
- 시나리오 생성/목록/상세/수정/논리 삭제
- 시나리오 버전 생성/그래프 저장/게시
- 키워드/유사어 저장
- 관리자 화면 진입점
- 감사 로그 적용

## 3. 구현 순서

1. Flyway `V3__scenario_baseline.sql`은 시나리오 baseline만 추가하고, `V3_1__auth_must_change_password.sql`에서 `users.must_change_password`를 분리 추가
2. `common`에 공통 REST 응답/에러 DTO와 예외 핸들러 추가
3. `domain.scenario` 하위 `controller/service/mapper/dto/model` 추가
4. `resources/mapper/scenario/ScenarioMapper.xml` 추가
5. `/admin/scenarios` Thymeleaf 화면 추가
6. 관리자 대시보드에 시나리오 관리 링크 추가
7. 서비스 메서드에 `@Audited` 적용
8. 단위/통합 테스트 추가

## 5. 수용 기준

- `mvn test` 성공
- 애플리케이션 기동 시 Flyway V3/V3.1 적용 성공
- Flyway V3.1 적용 후 기존 ADMIN은 `must_change_password=false`, OPERATOR 시드는 `enabled=false`, `must_change_password=true` 기준 충족
- ADMIN/OPERATOR만 시나리오 관리 접근 가능
- 시나리오 생성 후 목록/상세 조회 가능
- 초안 버전 생성 후 노드 그래프 저장 가능
- 시작 노드 없는 버전 게시는 실패
- 게시된 버전만 활성화 가능
- 생성/수정/삭제/게시/활성화 이벤트가 `audit_log`에 저장
- 유효하지 않은 입력은 400 공통 응답 반환

## 6. 구현 주의

- 기존 M1 인증/감사 구조를 변경하지 않는다.
- MyBatis `${}`를 사용하지 않는다.
- 게시된 버전은 직접 수정하지 않는다.
- 대량 UI 편집기는 M2에서 단순 폼/JSON textarea 수준으로 시작해도 된다.
- M3 챗봇 런타임 로직은 이번 범위에서 제외한다.
- OPERATOR 운영 기본 계정은 비활성 상태로 시딩하고 `must_change_password=true`로 생성한다. 해당 컬럼은 V3.1 마이그레이션에서 추가한다.
- 쿠키는 `SameSite=Lax`, `Secure=true`, `HttpOnly=true`를 기본으로 하며 CSRF 토큰 쿠키만 `HttpOnly=false` 예외를 둔다.
- `server.forward-headers-strategy=framework`를 사용하고 프록시 헤더 부팅 경고는 prod 프로파일에서만 출력한다.
- M3 매칭 캐시 TTL 기본값은 300초로 문서 기준을 맞춘다.
