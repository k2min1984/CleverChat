# M4 검색 설계지시서

> 작성일: 2026-05-11
> 대상 프로젝트: `3.개발/cleverchat`
> 기준 문서: `2.설계/03.API설계서/M4_검색API.md`, `2.설계/02.DB설계서/M4_검색ERD.md`, `2.설계/06.운영메모/M4_검색_운영메모.md`

## 0. 진입 전제

M4는 M3 자유 텍스트 fallback을 실제 검색 결과로 연결하는 단계다. 구현 전 아래 조건을 확인한다.

| 항목 | 기준 |
|---|---|
| 선행 마이그레이션 | Flyway `V1`~`V4__chat_runtime_baseline.sql` 적용 |
| 선행 도메인 | M2 시나리오, 버전, 노드, 키워드, 유사어 조회 가능 |
| 선행 인터페이스 | M3 `FallbackSearchService` 또는 동등 인터페이스 존재 |
| DB 권한 | 운영 PostgreSQL에서 `pg_trgm`, `unaccent` 확장 생성 가능 여부 확인 |
| 보안 | M3 `PiiGuard` 재사용, PII 차단 시 원문 검색어 저장 금지 |

M2/M3 구현이 없거나 M3 fallback 인터페이스가 없으면 M4 구현 전 해당 계약을 먼저 만든다.

## 1. 설계 결정

| 영역 | 결정 |
|---|---|
| 검색 엔진 | PostgreSQL FTS `simple` configuration + `pg_trgm` + `unaccent` |
| 한국어 형태소 분석 | 미도입. 품질 임계 도달 시 mecab-ko, PGroonga, 외부 검색엔진 재검토 |
| 검색 대상 | 시나리오 제목/설명, 노드 본문, 키워드, 유사어 |
| 랭킹 | 제목 > 키워드/유사어 > 노드 본문 > 최신 게시 버전 우선 |
| 캐시 | 사용하지 않음. 시나리오 게시 정합성을 우선한다 |
| 로그 | `search_log`, `search_block_log` 분리. 차단 로그에는 원문 미저장 |
| 보존 | 검색 로그와 차단 로그 90일 보존 |
| 인기 검색어 | 일집계 배치. KST 03:30 실행 |
| 로그 파기 | `SearchLogRetentionService` 배치. KST 03:00 실행 |
| 관리자 화면 | 검색 로그, 차단 로그, 인기 검색어 3개 화면 |

## 2. Flyway V5 지시

파일: `3.개발/cleverchat/src/main/resources/db/migration/V5__search_baseline.sql`

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE EXTENSION IF NOT EXISTS unaccent;

ALTER TABLE scenario
    ADD COLUMN search_tsv tsvector
    GENERATED ALWAYS AS (
        setweight(to_tsvector('simple', unaccent(coalesce(title, ''))), 'A') ||
        setweight(to_tsvector('simple', unaccent(coalesce(description, ''))), 'C')
    ) STORED;

ALTER TABLE scenario_node
    ADD COLUMN search_tsv tsvector
    GENERATED ALWAYS AS (
        setweight(to_tsvector('simple', unaccent(coalesce(content, ''))), 'B')
    ) STORED;

CREATE INDEX ix_scenario_search_tsv ON scenario USING GIN (search_tsv);
CREATE INDEX ix_scenario_title_trgm ON scenario USING GIN (unaccent(title) gin_trgm_ops);
CREATE INDEX ix_scenario_node_search_tsv ON scenario_node USING GIN (search_tsv);
CREATE INDEX ix_scenario_node_content_trgm ON scenario_node USING GIN (unaccent(content) gin_trgm_ops);
CREATE INDEX ix_scenario_keyword_trgm ON scenario_keyword USING GIN (unaccent(keyword) gin_trgm_ops);
CREATE INDEX ix_scenario_synonym_trgm ON scenario_synonym USING GIN (unaccent(synonym) gin_trgm_ops);

CREATE TABLE search_log (
    id BIGSERIAL PRIMARY KEY,
    query_text VARCHAR(200) NOT NULL,
    normalized_query VARCHAR(200) NOT NULL,
    result_count INTEGER NOT NULL,
    top_scenario_id BIGINT NULL,
    source VARCHAR(20) NOT NULL,
    latency_ms INTEGER NOT NULL,
    anonymous_id_hash VARCHAR(64) NULL,
    user_id BIGINT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_search_log_top_scenario FOREIGN KEY (top_scenario_id) REFERENCES scenario(id) ON DELETE SET NULL,
    CONSTRAINT fk_search_log_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    CONSTRAINT ck_search_log_source CHECK (source IN ('CHAT_FALLBACK', 'ADMIN_TEST', 'API'))
);

CREATE INDEX ix_search_log_created ON search_log (created_at DESC);
CREATE INDEX ix_search_log_normalized_created ON search_log (normalized_query, created_at DESC);

CREATE TABLE search_block_log (
    id BIGSERIAL PRIMARY KEY,
    query_length INTEGER NOT NULL,
    pii_types VARCHAR(200) NOT NULL,
    source VARCHAR(20) NOT NULL,
    anonymous_id_hash VARCHAR(64) NULL,
    user_id BIGINT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT fk_search_block_log_user FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL,
    CONSTRAINT ck_search_block_log_source CHECK (source IN ('CHAT_FALLBACK', 'ADMIN_TEST', 'API'))
);

CREATE INDEX ix_search_block_log_created ON search_block_log (created_at DESC);

CREATE TABLE popular_query_daily (
    stat_date DATE NOT NULL,
    normalized_query VARCHAR(200) NOT NULL,
    query_text_sample VARCHAR(200) NOT NULL,
    search_count INTEGER NOT NULL,
    no_result_count INTEGER NOT NULL,
    top_result_scenario_id BIGINT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (stat_date, normalized_query),
    CONSTRAINT fk_popular_query_top_scenario FOREIGN KEY (top_result_scenario_id) REFERENCES scenario(id) ON DELETE SET NULL
);

CREATE INDEX ix_popular_query_daily_count
    ON popular_query_daily (stat_date DESC, search_count DESC);
```

주의:

- `scenario`와 `scenario_node` 매퍼가 `INSERT RETURNING *`를 사용한다면 generated column 매핑 충돌 여부를 먼저 확인한다.
- 운영 DB에서 확장 생성 권한이 없으면 배포 전 DBA 작업으로 분리한다.


`PostgresFtsFallbackSearchService`는 M3 `FallbackSearchService`를 구현한다. 토글은 아래 프로퍼티를 사용한다.

```yaml
cleverchat:
  search:
    enabled: true
    max-query-length: 200
    max-results: 5
    log-queue-capacity: 1000
    popular-query-cron: "0 30 3 * * *"
    retention-days: 90
    retention-cron: "0 0 3 * * *"
```

`SearchLogRetentionService`의 `@Scheduled`는 `retention-cron`을 사용하고 `zone = "Asia/Seoul"`로 고정한다.

DTO/모델 필드 기준:

| 항목 | 필드 |
|---|---|
| `SearchResultCard` | `scenarioId`, `scenarioTitle`, `matchedField`, `score`, `snippet` |
| `SearchBlockLog.piiTypes` | DB `pii_types` 문자열을 서비스/응답 계층에서 `List<String>`으로 변환 |
| `AdminSearchBlockResponse.piiTypes` | `List<String>` |

## 4. 검색 쿼리 규칙

- 입력은 trim 후 1~200자(Java `String.codePointCount(0, length())` 기준 코드포인트 수)로 제한한다. 이모지·서러게이트 페어가 1자로 계수되도록 `length()` 직접 사용은 금지한다.
- `unaccent`, lower-case, 연속 공백 축약으로 정규화한다.
- PostgreSQL `LIKE`/`ILIKE` 또는 trigram 보조 검색에 전달하기 전 `%`, `_`, `\`는 escape 처리한다.
- 주민등록번호/카드번호 등 고위험 PII는 검색을 차단한다.
- 이메일/전화번호는 M3 정책과 동일하게 마스킹 저장 가능하나, 검색어 로그에는 마스킹된 값만 남긴다.
- `search_block_log.pii_types`는 정렬된 PII 타입 코드를 쉼표로 연결해 저장한다. 예: `CARD,RRN`
- 결과는 `PUBLISHED` 버전과 활성 시나리오만 노출한다.
- 결과가 없으면 `CHAT_NO_MATCH` 또는 `SEARCH_RESULT_EMPTY`를 호출 맥락에 맞게 반환한다.

## 5. 랭킹 기준

| 항목 | 가중치 |
|---|---:|
| 시나리오 제목 FTS/trigram | 1.00 |
| 키워드/유사어 일치 | 0.85 |
| 노드 본문 FTS | 0.60 |
| 시나리오 설명 | 0.35 |
| 최근 게시 버전 보정 | 0.05 |

동일 시나리오가 여러 노드에서 매칭되면 최고 점수 1건만 카드로 반환한다.

## 6. M3 연결

`free-text` 처리 흐름은 다음과 같다.

1. M3 키워드/유사어 직접 매칭을 먼저 시도한다.
2. 직접 매칭 실패 시 M4 `FallbackSearchService.search()` 호출.
3. 검색 결과가 있으면 `FreeTextResponse.fallbackCards`에 카드 목록을 채운다.
4. 검색 결과가 없으면 `chat_failure`에 `NO_MATCH`를 남긴다.
5. PII 차단이면 검색 로그 원문 없이 `search_block_log`만 저장한다.

## 7. 관리자 API

상세 계약은 `2.설계/03.API설계서/M4_검색API.md`를 따른다.

| Method | Path | 설명 |
|---|---|---|
| GET | `/admin/api/search/logs` | 검색 로그 조회 |
| GET | `/admin/api/search/blocks` | PII 차단 검색 조회 |
| GET | `/admin/api/search/popular` | 인기 검색어 조회 |
| POST | `/admin/api/search/test` | 관리자 검색 테스트 |
| POST | `/admin/api/search/popular/rebuild` | 인기 검색어 재집계 |
| DELETE | `/admin/api/search/logs/expired` | 90일 초과 로그 파기 |

보존 파기 입력 검증 책임 계층:

| 계층 | 책임 |
|---|---|
| Controller(`AdminSearchApiController`) | `@RequestParam` 바인딩 시 `retentionDays` 정수형/범위(>=30) 검증, `dryRun` Boolean 파싱 오류는 `COMMON_INVALID_PARAMETER` 400으로 반환 |
| Service(`SearchLogRetentionService`) | 비즈니스 cutoff 산출(`now() - retentionDays`), `retentionDays` 미지정 시 프로퍼티 `cleverchat.search.retention-days` 기본값 적용, `dryRun=true`면 DELETE 미실행·count만 수행 |
| Mapper | DELETE/SELECT 분기 SQL만 담당. 입력 신뢰 가정, 추가 검증 없음 |
| Scheduler(`@Scheduled` 진입점) | 항상 `dryRun=false`와 프로퍼티 기본 `retentionDays` 사용. 외부 입력 없음 |

## 9. 운영

- 비동기 검색 로그 큐가 포화되면 검색 응답은 성공시키고 로그 폐기 카운터를 증가시킨다.
- 로그 폐기율이 5%를 초과하면 큐 크기, 배치 flush 간격, DB write latency를 점검한다.
- 검색 p95 500ms 초과가 반복되면 실행계획과 GIN 인덱스 사용 여부를 확인한다.
- 인기 검색어 재집계는 멱등해야 한다.

## 11. 인수 기준

- `pg_trgm`, `unaccent` 확장 포함 V5 마이그레이션이 적용된다.
- 자유 텍스트 fallback 결과가 실제 검색 카드로 반환된다.
- 관리자 검색 로그/차단 로그/인기 검색어 조회가 가능하다.
- 검색어 PII 차단 정책이 M3와 일관된다.
- 90일 보존 배치와 인기 검색어 일집계가 동작한다.
- `mvn test`가 통과한다.

## 13. 재검토 트리거

아래 중 하나가 발생하면 PostgreSQL FTS 유지 여부를 재검토한다.

- 한국어 검색 무결과율이 20%를 초과
- 검색 API p95가 1초를 지속 초과
- 시나리오/노드 본문 합산 100만 행 초과
- 형태소 기반 랭킹 요구가 운영 필수로 확정
- 크롤링 문서 검색까지 동일 엔진으로 처리해야 함
