## 1. M1 §2.3 서비스 계층 권한 검증 헬퍼

### 1.1 배경
URL/Interceptor 기반 권한 제어는 적용 완료. 서비스 진입점(특히 관리자 도메인 mutation)에서 권한을 한 번 더 확인하는 `RoleGuard`/`@RequireRole` 헬퍼도 기본형 구현 완료 상태다.

### 1.2 구현 단위
1. `security` 패키지에 `RoleGuard`/`@RequireRole` 헬퍼 추가 완료. 현재 코드 기준 타입은 `AdminSession` 또는 `AuthenticatedUser`를 사용하고, 문자열 role은 기존 `hasRole`/`hasAnyRole` 정규화 규칙을 따른다.
2. 관리자 mutation 진입점 — 시나리오 게시/노드 편집/공지/알림 webhook 변경/필드 암호화 backfill·rotate/사용자 잠금 해제 등 — 에서 헬퍼 호출 추가 완료.
3. 권한 위반 시 신규 예외를 늘리지 않고 기존 `BusinessException(ErrorCode.ACCESS_DENIED)` 흐름을 유지한다.

### 1.3 완료 기준
- 신규 단위 테스트 `RoleGuardTest` 통과 (allow/deny 매트릭스).
- 적용 대상 mutation 서비스 권한 경계는 `@RequireRole("OPERATOR")` 기준으로 보강 완료.
- 정적 검사: 적용 대상 서비스 메서드에 헬퍼 호출이 누락된 경우를 잡는 ArchUnit/JUnit 정적 테스트는 후속 품질 고도화로 둔다.

### 1.4 영향 범위
- WBS §2.3의 `[ ]` 항목을 `[x]`로 갱신.
- `2.설계/05.보안설계서/감사로그표준.md`에 권한 위반 감사 로그 또는 security event 기록 기준 추가.

## 4. M6 알림 adapter 고도화

### 4.1 배경
현재: Slack-compatible webhook + SMTP email 기본형 + env 기반 key rotation + `nextRetryAt` 기반 retry worker.
남은 구멍: provider별 payload/template mapping과 알림 운영 리포트가 정리되어 있지 않음. 단, 현재 `OpsNotificationService`에는 3회 재시도 상태(`RETRY`/`FAILED`), `nextRetryAt`, scheduled retry worker, 동일 source open event 재사용, previous env key fallback이 이미 구현되어 있으므로 중복 구현하지 않는다.

### 4.2 구현 단위
1. 필요 시 `NotificationAdapter` 인터페이스를 도입해 기존 generic webhook, Slack-compatible webhook, SMTP email 발송 분기를 얇게 감싼다. 기존 public API/DB 계약은 유지한다.
2. 채널별 payload template(JSON / text) — 이벤트 type → template 매핑 기준을 문서화하고, v1은 코드 상수 또는 enum 기반으로 시작한다.
3. retry worker는 기본형 구현 완료. 운영에서는 `cleverchat.notification.retry.fixed-delay-ms` 기본 60000ms를 기준으로 모니터링하고, 변경 필요 시 운영 설정으로 조정한다.
4. 동일 source open event 재사용 정책은 유지하고, 추가 dedup window가 필요하면 기존 `sourceType/sourceId/reviewed/status` 기준과 충돌하지 않게 설계한다.
5. 알림 이벤트 처리 현황(대기/재시도/실패/확인)을 관리자 화면 또는 운영 리포트에 요약한다.

### 4.3 완료 기준
- adapter 단위 테스트(전송 성공/실패/기존 fallback 경계).
- retry worker가 `nextRetryAt <= now`인 event만 처리하고 max attempt 이후에는 `FAILED`를 유지하는지 회귀 검증.
- open event 재사용 회귀 테스트.
- 운영메모에 provider 추가 절차 문서화.

1. **필드 암호화 운영 고도화**: backfill/rotate를 분할 처리(batch size, throttling), 진행률/실패 row 보고서 자동 생성. 키 회전 감사 로그 표준화.
2. **CSP nonce 적용 검토**: 현재 정적 CSP → 인라인 스크립트가 있는 화면은 nonce 기반으로 단계 전환(검토만, 적용은 후속 결정).
3. **세션 고정 방지**: 로그인 성공 시 세션 ID 재발급(`changeSessionId`)과 회귀 테스트 추가 완료.

### 6.2 접근성 자동화
1. axe-core 또는 Playwright Accessibility Scanner 기반 1차 점검 스크립트 추가(개발자 PC 수동 실행 기준).
2. `/chat`, `/admin/login`, `/admin/dashboard`, `/admin/scenarios/{id}/graph` 4화면 baseline 위반 0 유지.

### 6.3 성능
1. k6 시나리오 확장: `/chat` start → option select → free-text → feedback 1회 transaction.
2. slow query Top-N 자동 리포트(주간) — Logback rolling을 집계 스크립트로 변환.
3. Caffeine 캐시 히트율 metric 노출(`/admin/api/statistics/cache`).

### 6.4 완료 기준
- 영역별 단위·통합 테스트 통과 + 운영메모 갱신.
- 자동화 스크립트는 `4.테스트/03.성능/` 또는 `4.테스트/02.테스트시나리오/`에 배치.
