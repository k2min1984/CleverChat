# 시스템 설정 및 크롤링 상세 개선

작성일: 2026-09-22

후속 변경: 운영 정책 설정과 vLLM 호출, JSON 보관 정리, 서브경로 보완은 [V44 구현 결과](RESULT-runtime-settings-integration-2026-09-22.md)를 참고한다. 아래 내용은 최초 V43 구현 시점의 기록이다.

## 적용 내용

- 관리자 전용 시스템 설정 메뉴: `/admin/system-settings`
- 운영 방식: 독립(단독)은 기존 로그인, 연계는 게이트웨이 헤더 SSO
- 파일 저장: 크롤링 JSON의 서버 기본 폴더와 대상별 경로 재정의
- 크롤링 상세: 현재 작업·저장 문서 수·JSON 설정 요약과 수집 문서 / 실행 이력 / 대상 설정 탭
- 문서 제목·URL 검색 및 20건 단위 서버 페이지 조회. 목록에서는 본문 일부만 가져온다.
- 실행 중 5초 간격 상태 갱신. 창이 숨겨지거나 검색어 입력 중이면 갱신을 잠시 미룬다.
- 페이지별 로그와 게시판 수집 범위는 실행 이력 안에서 펼쳐서 확인한다.

## 운영 및 데이터

V43은 시스템 설정 테이블과 관리자 메뉴, 사용자 신원 출처·사번·조직 컬럼을 추가한다. 기본 운영 방식은 `LOCAL`, 기본 저장 폴더는 미설정이다. 기존 계정, 수집 문서, 대상별 JSON 설정은 유지된다.

시스템 설정은 ADMIN만 조회·변경할 수 있다. 저장에는 CSRF 검사, 감사 로그, 버전 충돌 검사를 적용한다. 인증 방식 또는 활성 연계 정보가 바뀌면 기존 세션을 만료시킨다. 독립 모드에서 연계 정보를 미리 작성하거나 파일 경로만 바꾸는 경우에는 로그인을 유지한다.

JSON 저장을 켠 대상은 **대상별 폴더 → 시스템 기본 폴더** 순으로 경로를 결정한다. 두 값이 모두 없으면 대상 저장을 거절한다. 기본 폴더를 사용하는 대상이 있으면 시스템 기본 폴더를 빈 값으로 변경할 수 없다. 폴더는 서버의 절대 경로이며 실제 쓰기 실패는 실행 이력에 남긴다. 경로 변경은 이후 파일에 적용하며, 기존 파일은 옮기지 않는다.

## SSO 적용 범위

연계로 저장하려면 게이트웨이 주소와 서버 환경변수 `CLEVERCHAT_GATEWAY_SHARED_SECRET`이 필요하다. 시크릿은 화면이나 DB 설정에 저장하지 않는다.

- `X-Clever-Gw-Secret`을 검증한 뒤 사용자 헤더를 신뢰한다.
- `X-Clever-User` 사번으로 GATEWAY 계정을 생성·갱신하며 비밀번호는 NULL이다.
- 이름·조직은 퍼센트 인코딩을 해석한다.
- 서비스 ID에 해당하는 ADMIN / OPERATOR / USER만 적용한다. 플랫폼 관리자 헤더 값 1은 ADMIN으로 매핑한다.
- 역할은 요청마다 갱신하며, 신원 누락·잘못된 시크릿·미지의 역할·중지된 계정은 거절한다.
- 연계에서는 로컬 비밀번호 인증을 수행하지 않는다. 로그인 페이지는 설정된 포털 주소로 이동할 수 있는 화면을 제공한다.
- SSO 대화 이력과 소유권 검증은 내부 사용자 번호를 사용한다.

현재 구현은 실제 게이트웨이를 연결할 수 있는 기반이다. 외부 게이트웨이를 통한 접속·프록시 경로·로그아웃 연동 검증, 위임 로그인, 기존 로컬 계정/비밀번호를 제거하는 통합 배포 전환 절차, 통계 및 문서 투입 API는 별도 작업이다. 연계 전환은 로컬 계정을 삭제하지 않는다. 모의 SSO 옵션은 제품 화면에 추가하지 않았다.

잘못된 연계 설정으로 관리자 접근이 막힌 경우에는 서버 운영자가 DB에서 독립 모드로 복구할 수 있다. 아래 SQL은 기존 로컬 관리자 계정으로 다시 로그인하도록 복구하며, 권한 없이 인증을 생략하는 기능은 아니다.

```sql
UPDATE cleverchat_dev.tb_system_settings
SET operation_mode = 'LOCAL', version = version + 1,
    auth_version = auth_version + 1,
    updated_by = 'operator-recovery', updated_at = now()
WHERE id = 1;
```

운영 스키마 이름이 다르면 해당 스키마로 바꾼다.

## 검증

- 단위·PostgreSQL 통합 테스트 443건 중 437건 통과, 기존 조건부 테스트 6건 건너뜀. 분리 검증 디렉터리의 문서 누락을 보완한 뒤 관련 검사를 재실행하여 통과했다.
- V43 마이그레이션, 관리자 접근 제한, CSRF, 기본 폴더/대상 폴더 실제 JSON 생성, SSO 신원·역할, 대화 소유권, 상세 페이지 렌더링과 20건 페이지 조회를 검증했다.
- 별도 DB와 로컬 QA 서버에서 JDBC 세션을 사용하여 로그인, 설정 저장, 연계 전환, 위조 헤더 거절, 역할 변경, 독립 복귀를 실제 HTTP로 검증했다.
- JavaScript 구문 검사와 변경 Java 파일 포맷 검사를 통과했다.
- 연결 가능한 브라우저가 없어 실제 브라우저의 시각적 검수는 수행하지 못했다.
