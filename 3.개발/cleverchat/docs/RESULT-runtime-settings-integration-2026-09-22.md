# 운영 설정 화면 및 연계 보완

작성일: 2026-09-22

## 화면과 적용 방식

`/admin/system-settings`를 다음 다섯 탭으로 구성했다. ADMIN만 접근·저장할 수 있으며, CSRF 검사와 설정 버전 충돌 검사, 변경 감사 기록을 적용한다.

| 탭 | 설정 |
|---|---|
| 로그인·연계 | 독립/게이트웨이 SSO, 포털 주소, 서비스 ID, 접속 인증 방식·배포 경로 확인, 독립 로그인 실패 횟수·잠금 시간, 로그인 세션 만료 |
| 파일·보관 | JSON 기본 폴더, 실패·중복 문서/수집 로그 보관일, 자동 정리 여부·시각, 검색 로그 정리 기본 보관일, JSON 보관일·자동 정리 |
| 크롤링 | 새 작업 처리 사용 여부, 브라우저 수집, 발견 URL·게시판 페이지·문서 제한, 실패 작업 복구 기준, 재시도·응답 대기 |
| 검색·챗봇 | 검색 후보·그룹별 표시 기준·관련도·더보기, 대화 만료·조회 범위·안내 문구, 요청 제한 |
| AI 연결 | vLLM 주소·모델·사용 여부·대기 시간·답변 토큰·다양성, 저장된 주소의 모델 확인 |

영역별 저장이므로 다른 탭의 값을 함께 덮어쓰지 않는다. 다른 영역에 저장하지 않은 편집이 있으면 현재 영역을 저장하기 전에 안내한다.

V44의 `tb_system_settings.runtime_settings`에 저장한다. 설정하지 않은 값은 기존 환경변수/설정 파일 또는 기존 코드 기본값을 사용한다. 저장된 영역은 DB 값이 우선한다. 서버 비밀번호·API 키·DB 연결·브라우저 실행 파일 경로는 환경변수에 유지한다.

- 저장한 값은 재시작 없이 반영한다. 다른 서버 인스턴스의 설정 캐시는 최대 1초 후 갱신한다.
- 수집 작업은 시작 시 운영 설정을 고정하며 다음 작업부터 변경을 적용한다. 수집 실행을 끄면 현재 작업을 마친 뒤 새 작업을 시작하지 않는다.
- 대화 만료는 이후 생성·활동부터, 로그인 세션 만료는 다음 요청부터 반영한다. 기존 계정 잠금의 만료 시각은 소급 변경하지 않는다.
- 검색의 기존 그룹별 표시 규칙을 유지한다. 문서 후보가 표시 기준 안에 있으면 모두 표시하며, 기준을 넘으면 관련도와 문서 표시 상한을 적용한다. 최소 점수에 모두 미달하면 최상위 1건을 유지한다.
- 대상별 URL·수집 일정·폴더 재정의와 알림 채널 관리는 기존 기능별 화면에 유지한다.

## 자동 정리

기존의 DB 정리 범위를 유지한다. 실행 로그는 등록 시각 기준, 문서는 등록 시각과 `FAILED`/`DUPLICATE` 상태를 기준으로 삭제하며 **성공 문서는 삭제하지 않는다**. 기본값은 로그 365일, 실패·중복 문서 90일이다. 검색 로그 보관일은 기존 수동 정리 기능의 기본값이며 새 자동 검색 로그 삭제는 추가하지 않았다.

자동 정리는 한국 시간의 지정된 분에 실행하고, 날짜별 DB 실행 기록으로 중복 수행을 막는다. 기본 시각은 03:45다. 설정을 저장하거나 서버를 켰다는 이유로 지난 정리를 즉시 실행하지 않는다. 최근 실행 결과는 파일·보관 탭에서 확인한다. 실행 시각에 서버가 정지되어 있었다면 해당 일의 정리는 소급 실행하지 않는다.

JSON 자동 정리 기본값은 꺼짐이다. V44 이후 생성하면서 `tb_crawl_export_file`에 등록한 파일만 대상이다. 저장 당시의 실제 루트·대상/날짜/UUID 경로·SHA-256 내용이 일치해야 삭제하며, 링크 경로나 수정된 파일은 건너뛴다. 기존 미등록 JSON이나 관리자가 둔 파일은 폴더에 함께 있어도 건드리지 않는다. 한 번에 최대 1,000건 처리하며 폴더 자체는 삭제하지 않는다. 여러 서버에서 정리할 때는 등록된 저장 경로를 같은 공유 경로로 마운트해야 한다.

## SSO와 서비스 경로

기존 공유 시크릿 검증·요청별 역할 갱신·사번 기반 JIT·로컬 비밀번호 로그인 차단을 유지했다. UI에는 실제 접속 인증 방식과 서비스 경로를 표시한다.

`CLEVERCHAT_CONTEXT_PATH=/cleverchat`처럼 서버 배포 경로를 지정할 수 있다. 게이트웨이에서는 이 프리픽스를 유지해 프록시해야 한다. 관리자/챗봇 HTTP 요청과 이력 링크에 컨텍스트 경로를 적용했다. 이 값은 서버 기동 설정으로서 변경 시 재시작이 필요하며, 서비스 ID를 화면에서 바꾸는 것만으로 배포 경로가 바뀌지는 않는다.

전체 `INTEGRATION_GUIDE_v1.0.md` 이행 완료를 뜻하지 않는다. 실제 게이트웨이 연결·등록 검증, 위임 로그인, 통합 현장의 기존 LOCAL 비밀번호 정리, 이용 통계 전송과 문서 투입 API는 별도 계약/전환 작업이다. 운영 방식 변경만으로 기존 계정을 삭제하지 않는다.

## vLLM

vLLM의 [OpenAI 호환 API](https://docs.vllm.ai/en/latest/serving/openai_compatible_server.html)에 맞춰 `/v1/models`와 `/v1/chat/completions`를 사용한다. 기본 주소는 `http(s)://서버[:포트]/v1`이며 게이트웨이 경유 시에도 `/v1`으로 끝나는 해당 API 주소를 지정한다. 다른 클라우드 모델로 자동 전환하지 않는다.

환경변수 기본값:

```text
CLEVERCHAT_VLLM_BASE_URL
CLEVERCHAT_VLLM_MODEL
CLEVERCHAT_VLLM_API_KEY
```

API 키는 서버 환경변수로만 주입하며 화면에는 등록 여부만 표시한다. 모델 확인 버튼은 저장된 주소의 모델 목록에 설정 모델이 존재하는지 확인한다. 실제 답변 생성 성공까지 보장하는 검사는 아니다.

AI 답변을 켜면 기존 검색에서 선택한 근거·질문으로 답변을 생성한다. 단일 크롤링 문서 또는 선택한 문서도 사용할 수 있으며 원문 링크를 유지한다. 호출 실패·시간 초과·빈 답변이면 기존 검색 안내/문서 요약으로 돌아간다. 응답 크기 제한과 리디렉션 차단을 적용했고 원격 오류 본문과 API 키를 화면에 내보내지 않는다. 실제 vLLM 개발서버 주소·모델명이 제공되지 않아 현재 개발 서버의 AI 사용 기본값은 꺼짐이다.

## 검증 결과

- 전체 회귀 465건: 459건 통과, 기존 조건부 검사 6건 건너뜀.
- 별도 실제 HTTP 통합 검사 1건 통과. 합계 466건 중 460건 통과, 6건 건너뜀.
- 실제 HTTP 검사: 독립 로그인 → 영역별 설정 저장 → 기본 경로를 상속한 로컬 페이지 수집 → JSON 파일 및 생성 이력 확인 → 테스트 vLLM 응답 → SSO 전환·위조 헤더 거절 → 독립 복귀.
- `/cleverchat` 컨텍스트 경로와 JDBC 세션을 사용한 서버에서 검증했다. 테스트 DB와 HTTP 대상은 모두 격리된 로컬 fixture다.
- JSON 정리에서 수정된 파일·미등록 파일 보존, 잘못된 경로 거절, 설정 범위·수치 검증, 수집 중 설정 고정, 날짜별 자동 정리 중복 방지를 확인했다.
- 변경 Java 파일 포맷, JavaScript 14개 구문, 루트/서브경로 URL 조립 및 공백 검사를 통과했다.
- 실제 외부 게이트웨이/vLLM 서버 및 브라우저 시각 검수는 수행하지 않았다.
