# 최초 설치 기본 백데이터 정리 결과

작성일: 2026-09-29 · 요청: 메뉴·유저·코드·권한의 기본 데이터 준비

기존 Flyway가 만드는 기본값을 새 DB에서 확인하고 배포용 목록과 SQL로 정리했다. 일반 설치는 기존처럼 Flyway를 사용하며, 실행 스크립트가 최초 관리자 생성 뒤 기본 데이터와 권한 연결까지 검사한다.

## 제공 내용

- [기본 백데이터 안내](../deploy/seed/README.md): 전체 메뉴·공통코드 그룹·권한 구성과 초기화 방법.
- [기본값 목록](../deploy/seed/basic-data-manifest.json): 새 설치에서 추출한 참조 데이터만 포함한다.
- [초기화 SQL](../deploy/seed/basic-data.sql): 구조가 준비되고 CMS 네 테이블이 모두 비어 있는 경우에만 기본값을 넣는다.
- [읽기 전용 검사 SQL](../deploy/seed/check-basic-data.sql): 역할·메뉴·코드·메뉴 권한·상위 연결·시스템 설정·LOCAL 관리자 연결을 검사한다.
- [생성 도구](../tools/build_basic_data.py): 명시된 참조 필드만 허용하고 manifest에서 SQL 두 개를 생성한다. 설치에는 Python이 필요하지 않다.
- [설치 실행 스크립트](../tools/start-local.ps1): 처음 계정을 준비할 때 누락이 있으면 완료 전에 중단하고, 기존 환경의 변경 사항은 경고하며 유지한다.

[README.md](../../../README.md), 앱 README, 인수인계 문서에서 기본 백데이터 안내로 이동할 수 있다. 관리자 ID 길이도 로그인 화면과 동일한 3~50자로 맞췄다.

## 새 설치 구성

| 항목 | 확인 결과 |
|---|---|
| 로그인 역할 | ADMIN / OPERATOR / USER, 3개 |
| CMS 권한 그룹 | 3개 |
| 메뉴 | 27개, 수집 문서/실행 로그 개별 메뉴 2개는 숨김 |
| 메뉴 권한 연결 | ADMIN 27개 + OPERATOR 22개 = 49개 |
| 공통코드 | 루트 1개 + 그룹 20개 + 상세 73개 = 94개 |
| 시스템 설정 | LOCAL 기본 행 1개 |
| 사용자 | 설치 시 입력한 최초 관리자 1명 |
| 사용자 역할 | 최초 계정에 ADMIN / OPERATOR 연결 |

사용자 행이나 비밀번호를 운영 DB에서 복제하지 않았다. 공용 비밀번호를 가진 운영자/일반 사용자 계정도 추가하지 않는다. 기존 설치의 계정·비밀번호·역할은 유지한다.

## 검증

검증용 컨테이너 `cleverchat-seed-verify-20260929`, DB 호스트 포트 15440, 앱 포트 18096을 사용했다. 기존 개발 DB와 별도 볼륨이다.

| 검증 | 결과 |
|---|---|
| 완전히 빈 DB 설치 | SQL migration 47개 성공, 마지막 V44, 업무 테이블 42개 |
| 최종 스크립트로 새 설치 재검증 | 기본 데이터/관리자 연결 검사 통과 후 READY, health UP |
| 기본값 목록 비교 | 새 설치의 참조 데이터가 manifest와 일치 |
| 최초 관리자 로그인 | HTTP 세션/쿠키를 이용한 로그인 성공 및 관리자 화면 도달 |
| 메뉴 구성 | 로그인 후 시나리오·정렬·크롤링·코드·메뉴·권한·시스템 설정 링크 확인 |
| 관리 화면 접근 | 코드/메뉴/권한/시스템 설정 화면 HTTP 200 |
| 초기화 SQL 재실행 | 기존 참조 데이터와 사용자 정보 유지, 중복 생성 없음 |
| 사용자 변경값 보존 | 테스트용 메뉴 이름 변경 및 OPERATOR 수정 권한 축소 후에도 초기화 SQL이 덮어쓰지 않음 |
| 권한 차이 검출 | 축소한 메뉴 권한이 읽기 전용 검사 결과에 표시됨 |
| 일부 CMS 테이블만 비어 있음 | 오류로 중단, 나머지 데이터 유지 |
| CMS 네 테이블이 모두 비어 있음 | 기본값 복원 후 manifest 일치 및 검사 통과 |
| 사용자 보존 | CMS 초기화 전후 사용자 정보 지문 동일 |
| 시퀀스 | 초기화 후 자동 번호로 권한 그룹/메뉴/코드 추가 시 PK 충돌 없음. 검증 행은 롤백 |
| 생성 도구 | 반복 생성한 SQL 내용 동일, 허용 필드 및 문서 링크 검사 통과 |
| PowerShell | 구문 분석 통과, 실제 실행 및 CheckOnly 통과 |
| 기존 개발 환경 | 읽기 전용 기본 데이터 검사 통과, 기존 8080 서버 health UP |

검증 후 해당 앱 프로세스·컨테이너·볼륨·네트워크를 정리했다. 실행 스크립트가 만든 임시 드라이브도 해제되었으며 기존 R: 연결과 개발 DB는 유지했다. 검증 앱은 PID와 실행 포트를 확인한 뒤 종료했으므로 마지막 실행 로그의 종료 코드 -1은 테스트 종료에 따른 것이다.

이번 변경은 데이터 파일·실행 스크립트·문서 범위다. 이전에 빌드한 JAR로 설치 흐름을 검증했으며 전체 Java 테스트를 다시 수행하지 않았다. 로그인/화면 접근은 HTTP로 확인했고 브라우저 시각 검수, SSO/vLLM 연동, 신규 PC의 JDK/Docker 설치 자체는 검증 범위에 포함하지 않았다.
