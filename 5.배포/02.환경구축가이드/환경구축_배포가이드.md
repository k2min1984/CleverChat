## 요구 환경

| 항목 | 기준 |
|---|---|
| 애플리케이션 | JDK 17, Maven 3.9+ 또는 저장소 Maven Wrapper |
| DB | PostgreSQL 16 계열. 확인한 개발 DB는 16.13, DB `cleverchat`, 스키마 `cleverchat_dev` |
| 개발 DB | Docker Compose, 호스트 5433 → 컨테이너 5432, named volume 유지 |
| 통합 테스트 | Docker Engine와 Testcontainers 사용 가능 환경 |
| 동적 게시판 수집 | Playwright Java 1.49.0과 일치하는 Chromium, OS 의존 라이브러리, 실행 계정 접근 권한 |
| 운영 | 실행 가능 JAR + 물리 PostgreSQL + HTTPS 리버스 프록시. 운영용 Compose는 사용하지 않음 |

개발자별 JDK/Maven 설치 절대 경로를 다른 서버에 복사하지 않는다. 빌드와 운영 프로세스가 실제로 Java 17을 사용하는지 `java -version`, `mvn -version`으로 확인한다.

## 로컬 자동 실행 상세

처음 설치하는 순서는 [저장소 README](../../README.md)에 있다. 이 절은 추가 옵션이나 오류 확인이 필요할 때 사용한다. 아래 명령의 작업 위치는 `3.개발/cleverchat`이다.

```powershell
.\start-local.cmd
```

실행 스크립트가 JDK 17의 java/javac와 로컬 Docker Desktop의 Linux 엔진을 확인하고, PostgreSQL 컨테이너 생성/기동, TCP 비밀번호 인증, Flyway 이력 검사, Maven Wrapper 빌드, 최초 관리자 준비 및 기본 데이터 검사를 수행한다. 자동 빌드는 `-DskipTests package`이므로 테스트 검수는 아래 빌드 및 검증 절차에서 따로 수행한다.

신규 계정은 영문/숫자로 시작하는 3~50자 ID(영문·숫자·점·밑줄·하이픈)와 12자 이상/UTF-8 72바이트 이내 비밀번호를 입력받는다. 공용 비밀번호를 만들지 않는다. 기존 계정이 있으면 계정·비밀번호·역할을 유지한다. 최초 계정은 기존 시더의 LOCAL OPERATOR에 ADMIN을 연결하며, 최초 부여는 앱 감사 로그 대신 구축 작업 기록으로 관리한다.

| 목적 | 명령 |
|---|---|
| 실행 전 읽기 전용 점검 | `.\start-local.cmd -CheckOnly` |
| 다른 앱 포트 사용 | `.\start-local.cmd -Port 8081` |
| 빌드된 JAR 재사용 | `.\start-local.cmd -SkipBuild` |
| 자동화 환경에서 입력 없이 실행 | `.\start-local.cmd -NonInteractive` |
| 별도 빈 DB로 설치 검증 | `.\start-local.cmd -DatabaseContainer cleverchat-setup-test -DatabasePort 15433 -Port 18080` |

`-CheckOnly`는 DB 생성/기동·빌드·서버 실행을 하지 않는다. DB가 없거나 멈췄거나 앱 포트가 사용 중이면 종료 코드 1이며 일반 실행 또는 충돌 원인 확인이 필요하다. 정상 점검은 종료 코드 0이다. 기존 기본 데이터와의 차이는 경고로 표시하므로 종료 코드와 함께 확인한다.

`-SkipBuild`는 현재 소스로 빌드한 `target/cleverchat.jar`가 있을 때만 사용한다. `-NonInteractive`의 신규 설치는 `CLEVERCHAT_SETUP_ADMIN_USERNAME`과 `CLEVERCHAT_SETUP_ADMIN_PASSWORD`를 비밀 환경값으로 제공해야 하며, 없으면 중단한다. 실제 비밀번호를 문서나 명령 인자에 적지 않는다.

자동 실행은 dev/DB `cleverchat`/스키마 `cleverchat_dev`로 고정하며 기본 DB 포트는 5433이다. 서버는 `127.0.0.1`에만 열린다. 외부 DB, 다른 PC 접속, stage/prod는 수동 배포 절차를 따른다. DB_URL·DB_USER·프로파일이나 Spring datasource/Flyway/config 외부 설정이 로컬 기준과 충돌하면 중단한다.

기본 데이터는 [메뉴·코드·역할·권한 목록](../../3.개발/cleverchat/deploy/seed/README.md)과 비교한다. 새 계정을 준비할 때 필수 데이터가 누락되면 READY 전에 중단하고, 기존 환경의 의도적인 변경은 경고하며 유지한다. Flyway 이력 없는 기존 테이블을 자동 baseline하거나 실패 이력을 지우지 않는다.

Ctrl+C는 실행한 앱만 종료하며 DB 컨테이너와 데이터는 보존한다. 스크립트가 만든 임시 드라이브도 해제한다. 다른 컨테이너명을 지정한 설치 검증은 별도 Compose 프로젝트/볼륨을 사용한다. 같은 DB를 사용하는 앱을 여러 포트에서 동시에 실행하면 예약·수집 작업도 중복 실행될 수 있다.

## 자동 실행 문제 해결

| 메시지/증상 | 조치 |
|---|---|
| java/javac가 없거나 버전이 다름 | JDK 17과 JAVA_HOME/PATH 확인 후 새 PowerShell에서 실행 |
| Docker가 준비되지 않음 | Docker Desktop의 Linux containers 모드와 로컬 context 확인 |
| 5433 사용 중 또는 예상과 다른 DB 컨테이너 | 기존 DB/컨테이너 설정 확인. 초기화하지 않고 충돌 원인 해결 |
| Port 8080 is in use | 기존 서버 이용 또는 해당 서버 종료 후 실행. 필요하면 `-Port 8081` 사용 |
| PostgreSQL query failed | 기존 DB 비밀번호 확인. 변경된 로컬 비밀번호는 DB_PASSWORD로 제공 |
| DB_URL/프로파일 또는 Direct Spring ... overrides 오류 | 새 터미널에서 로컬 실행하거나 외부 설정을 사용하는 수동 배포 절차 이용 |
| Flyway 이력이 없거나 실패 이력 존재 | DB 담당자와 이력/스키마 확인. 임의 repair/이력 삭제 금지 |
| Maven 다운로드/빌드 실패 | 콘솔 첫 오류, 사내 다운로드/프록시 설정 확인 |
| READY 이전 종료 또는 서버 종료 | 앱 폴더의 `logs/local-<포트>-<시각>.out.log`, `.err.log` 확인 |
| 최초 ADMIN 준비 실패 | 계정만 생성되었을 수 있으므로 아래 최초 계정 준비 절차로 대상과 역할 연결 확인 |
| Base data differs ... | 기본 백데이터 문서의 검사 결과 확인. 기존 사용자 변경값을 무조건 복원하지 않음 |
| 로그인 후 시나리오/수집 문서가 없음 | 새 설치에는 기존 콘텐츠가 포함되지 않음. 업무 데이터 등록 또는 승인된 DB 백업 인수 |

## 실행 후 설정

- **시스템 설정 → 파일·보관**에서 JSON 기본 저장 폴더를 서버 절대 경로로 지정하고 크롤링 대상의 JSON 저장도 선택한다. 대상별 폴더를 입력하면 기본 폴더보다 우선한다. 저장 결과는 대상 상세의 실행 이력에서 확인한다.
- 일반 HTML 수집에는 Chromium이 필요 없다. 동적 게시판은 아래 브라우저 수집 준비를 완료한 뒤 브라우저 수집을 활성화한다. 기본 실행 스크립트가 Chromium을 설치하지는 않는다.
- 최초 로그인 방식은 독립(LOCAL)이다. vLLM·Gateway SSO는 실제 주소·모델·서비스 ID·인증정보 준비 후 [외부 연계 인계](../06.인수인계/외부연계_인수인계.md)에 따라 설정한다. 기존 DB의 로그인 모드·운영값은 유지한다.

## 개발 환경 수동 실행

작업 위치는 `3.개발/cleverchat`이다. 아래 명령의 DB 사용자/비밀번호는 개발 Compose 설정에 맞춰 환경으로 먼저 제공한다. 운영 인증정보를 개발 기본값으로 맞추지 않는다.

```powershell
docker compose -f docker/docker-compose.yml up -d
docker compose -f docker/docker-compose.yml ps

$env:DB_URL = 'jdbc:postgresql://localhost:5433/cleverchat?currentSchema=cleverchat_dev,public'
$env:DB_SCHEMA = 'cleverchat_dev'
# DB_USER, DB_PASSWORD를 개발 DB에 맞게 주입
$env:SPRING_PROFILES_ACTIVE = 'dev'

.\mvnw.cmd clean package
java '-Duser.timezone=Asia/Seoul' -jar target/cleverchat.jar
```

한글 경로에서 Maven의 fork classpath가 깨지면 사용하지 않는 드라이브 문자로 앱 폴더를 연결한 후 실행한다. 기존 매핑을 먼저 확인하며 사용 중인 드라이브를 덮어쓰지 않는다.

```powershell
subst
# 아래 R:가 비어 있을 때에만 실행
subst R: (Split-Path -Parent $PWD.Path)
Set-Location R:\cleverchat
$env:MANAGEMENT_HEALTH_DISKSPACE_PATH = "$env:SystemDrive\"
.\mvnw.cmd spring-boot:run '-Dspring-boot.run.profiles=dev'
```

종료는 실행 터미널에서 Ctrl+C를 사용한다. 임시 드라이브 해제는 해당 서버/도구가 모두 종료된 뒤 다른 드라이브로 이동하여 `subst R: /D`로 수행한다. `.pid` 파일이 있다고 프로세스가 살아 있는 것은 아니므로 포트/프로세스를 확인한다. `docker compose down -v`는 개발 DB 볼륨까지 삭제하므로 일반 종료 명령으로 사용하지 않는다.

| 경로 | 기대 결과 |
|---|---|
| `/actuator/health` | 기동/DB 연결 정상 시 HTTP 200 및 UP |
| `/login` | LOCAL 로그인 화면. GATEWAY 모드는 연계 로그인 안내 |
| `/admin` | 관리자 권한 로그인 후 관리 화면 |
| `/admin/system-settings` | ADMIN 권한으로 설정 화면 |
| `/chat` | 상담 화면 |

기본 URL은 `http://localhost:8080`이다. `CLEVERCHAT_CONTEXT_PATH`를 설정했다면 모든 경로 앞에 해당 값을 붙인다. 포트 충돌 시 기존 8080 프로세스의 명령줄/소유자를 확인하고, 해당 앱인지 확인한 후 종료하거나 다른 포트로 실행한다.

## 최초 계정 준비

현재 dev와 prod의 기본 관리자 Flyway 시딩은 꺼져 있다. **stage는 설정 파일에서 켜져 있으므로**, 신규 stage DB를 초기화하기 전에 외부 설정으로 `spring.flyway.placeholders.default-admin-seed-enabled=false`를 명시한다. V4_1은 이미 적용되었다면 환경값만 바꿔도 재실행되지 않는다.

`InitialOperatorSeeder`는 `CLEVERCHAT_OPERATOR_SEED_USERNAME/PASSWORD`가 있으면 신규 **OPERATOR**를 만든다. `CLEVERCHAT_OPERATOR_SEED_ENABLED=true`여야 활성 계정이며 최초 로그인 비밀번호 변경 대상이다. enabled=false는 생성 차단이 아니라 비활성 계정 생성이다. 같은 username이 존재하면 비밀번호·역할·활성 상태를 갱신하지 않는다.

1. 최초 담당자 ID/일회용 비밀번호를 비밀 설정으로 주입하고 필요 시 위 시더로 활성 OPERATOR를 만든다.
2. 시스템 설정까지 관리할 최초 ADMIN이 없다면 DB 담당자가 해당 LOCAL 계정 1건을 확인한 후 ADMIN 역할을 부여한다. 아래는 **대상 스키마/계정을 확정한 뒤 사용하는 psql 예시**다. 사용자 생성이나 비밀번호 설정 SQL은 아니다.
3. 최초 로그인 및 비밀번호 변경 후 시더의 username/password 설정을 제거한다. 기존 기본 계정이 있다면 별도 점검한다.

```sql
-- psql -v bootstrap_username=<승인된 계정 ID>로 변수 제공.
-- cleverchat_dev는 예시이며 실제 대상 스키마로 교체한다.
BEGIN;
INSERT INTO cleverchat_dev.tb_user_role(user_no, role_no)
SELECT u.user_no, r.role_no
FROM cleverchat_dev.tb_user u
JOIN cleverchat_dev.tb_role r ON r.code = 'ADMIN'
WHERE u.username = :'bootstrap_username'
  AND u.auth_source = 'LOCAL' AND u.use_yn = 'Y'
ON CONFLICT DO NOTHING;
-- 해당 계정의 ADMIN 매핑 1건을 확인하고 COMMIT, 잘못된 대상이면 ROLLBACK.
SELECT u.username, r.code
FROM cleverchat_dev.tb_user u
JOIN cleverchat_dev.tb_user_role ur ON ur.user_no = u.user_no
JOIN cleverchat_dev.tb_role r ON r.role_no = ur.role_no
WHERE u.username = :'bootstrap_username';
```

이 수동 부여는 앱 감사 로그를 남기지 않으므로 초기 구축 작업 기록에 담당자/대상/시각을 남긴다. 평소 계정 관리는 관리자 화면을 사용한다. 관리자 IP 허용목록도 실제 프록시 뒤에서 확인한다.

## 브라우저 수집 준비

일반 HTML 수집에는 Chromium이 필요하지 않다. 동적 게시판은 서버 실행 계정이 접근할 수 있는 위치에 Java Playwright와 맞는 브라우저를 설치한다. 아래는 앱 폴더에서 사용하는 Maven CLI 예시다.

```powershell
# 필요 시 PLAYWRIGHT_BROWSERS_PATH를 서비스 계정이 읽고 실행 가능한 경로로 먼저 지정
.\mvnw.cmd org.codehaus.mojo:exec-maven-plugin:3.5.0:java '-Dexec.mainClass=com.microsoft.playwright.CLI' '-Dexec.args=install chromium'
```

Linux에서는 같은 Java CLI의 `install --with-deps chromium`을 사용할 수 있으며 OS 패키지 설치 권한과 사내망 반입 정책을 별도 확인한다. 이 문서 작업에서 새 서버의 Chromium 설치를 실행하지 않았다. 폐쇄망은 브라우저/네이티브 라이브러리 반입·체크섬·실행 권한을 확인한다. 웹 화면의 브라우저 수집 ON만으로 바이너리가 설치되지는 않는다.

## 빌드 및 검증

```powershell
.\mvnw.cmd clean test
.\mvnw.cmd spotless:check
# Docker 사용 가능 환경에서 통합 테스트
.\mvnw.cmd -Pit test
.\mvnw.cmd package
Get-FileHash target/cleverchat.jar -Algorithm SHA256
```

기본 테스트는 `integration` 태그를 제외한다. `-Pit test`는 기본 제외를 해제하며, 통합 테스트만 선택하려면 `-Pit -Dgroups=integration test`를 사용한다. Surefire 보고서는 `target/surefire-reports`에 있다. CI는 Windows에서 기본 테스트·Spotless·diff 검사를 수행하고, Docker 통합 작업은 현재 워크플로에 주석 처리되어 있다. CI 성공만으로 통합 검수가 완료되었다고 판단하지 않는다.

## stage/prod 배포

운영 주소·OS 계정·설치 경로는 아직 이 문서에서 확정하지 않았다. 다음 순서에 맞춰 현장 값을 지정한다.

1. JAR/커밋/해시와 테스트 결과를 확정하고, 기존 JAR·외부 설정·DB·JSON을 백업한다.
2. 서비스 계정에 JAR 읽기, 로그/JSON 폴더 쓰기, Chromium 실행 권한을 부여한다. 암호화 키 및 연계 시크릿은 별도 비밀 저장소에서 주입한다.
3. `SPRING_PROFILES_ACTIVE=stage` 또는 `prod`, `DB_URL`, **`DB_USERNAME`**, `DB_PASSWORD`를 지정한다. dev의 `DB_USER`와 다르다.
4. 현행 신규 설치는 `cleverchat_dev` 스키마를 사용하고 `DB_URL`의 `currentSchema`와 `spring.flyway.schemas/default-schema`를 일치시킨다. stage/prod에서는 `DB_SCHEMA`만 설정해도 적용되지 않는다. V20~V23이 스키마를 고정하므로 임의 이름으로 초기 설치하지 않는다. 다른 스키마가 필요한 배포는 기존 이력/체크섬을 보존할 마이그레이션 방안을 먼저 설계·검증한다. 스키마/확장 생성 권한도 DB 담당자와 확인한다.
5. 최초 ADMIN과 IP 허용목록, UTC/Asia/Seoul 기준, 보관 기간, 수집 허용 경로/호스트, Gateway 모드를 검토한다. 서비스 JVM은 `-Duser.timezone=Asia/Seoul` 권장.
6. 기존 앱을 정상 종료하고 새 JAR로 시작한다. Flyway 적용 로그와 health를 확인한다. 적용 실패 시 원인을 보존하고, 이력을 삭제하거나 `repair`로 무조건 통과시키지 않는다.
7. HTTPS 프록시와 직접 앱 포트 접근 통제를 적용한다. 프록시에서 Forwarded/X-Forwarded-* 값을 신뢰 가능한 값으로 재작성한다. 클라이언트가 보낸 Gateway 사용자/권한 헤더를 그대로 전달하지 않는다.
8. 로그인, 시스템 설정, 시나리오 선택/검색/이전, 수집 1건/JSON 생성, 외부 연계 검수를 수행한 뒤 트래픽을 연다.

실행 예시(외부 설정 파일은 별도로 준비):

```sh
java -Duser.timezone=Asia/Seoul -jar /opt/cleverchat/current/cleverchat.jar \
  --spring.profiles.active=prod \
  --spring.config.additional-location=file:/etc/cleverchat/application-prod.properties
```

`/opt/cleverchat`과 `/etc/cleverchat`은 예시 경로다. 운영 프로세스는 해당 명령과 서비스 계정·환경을 systemd 등 현장 서비스 관리자에 등록한다. 저장소에 실제 운영용 systemd/nginx 배포 설정은 확정되어 있지 않으므로 이를 준비·검증하는 항목은 [미결 사항](../06.인수인계/인수검수_미결사항.md)에 남겼다.

서브경로는 `CLEVERCHAT_CONTEXT_PATH=/cleverchat`처럼 설정한다. 프록시는 앱에 `/cleverchat/...`를 유지해서 전달해야 하며, 제거하면 라우팅·정적 자원·CSRF/리다이렉트 검수가 필요하다. stage/prod 쿠키는 secure이므로 HTTPS에서 검증한다.

## 롤백

health 실패, 핵심 로그인/상담/수집 장애, 데이터 손상 징후가 있으면 신규 트래픽을 제한하고 로그와 실패 원인을 보존한다. 새 앱을 중지한 뒤 **이전 JAR와 대응 설정**을 재배치한다. 이미 적용한 DB 변경이 이전 JAR와 호환되는지 먼저 확인한다. 호환되지 않으면 [복구 리허설](../05.백업복구절차서/복구리허설_체크리스트.md)에 따라 별도 DB에 백업을 복원하여 검증 후 전환한다. 일반 롤백에 DB DROP, Flyway 이력 삭제, 무검증 덮어쓰기를 포함하지 않는다.
