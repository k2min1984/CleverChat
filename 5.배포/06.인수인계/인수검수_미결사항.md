## 문서 작업에서 확인한 항목

- [x] 개발 DB 구조: 42개 테이블, 컬럼 427개, FK 52개, 인덱스 138개, 시퀀스 33개.
- [x] SQL 마이그레이션 47개(V44까지) 성공 상태 및 소스 파일명 대응. Flyway 스키마 생성 이력은 별도 1개.
- [x] 시스템 런타임 설정 40개를 enum의 타입/기본값/범위/property와 대조.
- [x] 현재 인증 모드·크롤링 파일 규격·주기 작업·로그·연계 호출을 소스에서 확인.

아래 항목은 **아직 인수 환경에서 수행 완료된 것으로 표시하지 않는다.** 과거 작업 결과의 테스트 통과는 날짜별 개발 근거이며 현장 검수를 대체하지 않는다.

## 미결 사항과 후속 작업

| 우선순위 | 항목 | 필요한 조치 | 담당 |
|---|---|---|---|
| 운영 전 필수 | 외부 Gateway 계약 | URL/service ID/역할 헤더, 중앙 로그아웃, 신뢰 경계와 직접 접속 정책 합의 | 연계/인프라 담당 지정 |
| 운영 전 필수 | 실제 vLLM | 주소/모델/키/전송 데이터 범위, 실제 생성·부하 검수 | AI/인프라 담당 지정 |
| 운영 전 필수 | 최초 ADMIN | 기본 공용 계정 대신 인수 계정, 초기 역할 부여/비밀번호 변경 기록 | 서비스/DB 담당 지정 |
| 운영 전 필수 | stage 기본 관리자 시딩 | stage yml은 현재 true. 신규 구축 전 false override 및 기존 계정 점검 | 배포 담당 지정 |
| 운영 전 필수 | 설치/운영 설정 | 실제 systemd/nginx 구성, 서비스 계정/경로/인증서/방화벽/시간대 확정 | 인프라 담당 지정 |
| 운영 전 필수 | 신규 설치 스키마 | V20~V23의 search_path가 cleverchat_dev로 고정. 다른 스키마가 필요하면 적용 이력을 보존하는 방안 설계·검증 | 개발/DB 담당 지정 |
| 운영 전 필수 | 키/백업 인수 | 현행·이전 암호화 키, DB+JSON 백업, 안전한 보관/실제 복구 검수 | 보안/DB 담당 지정 |
| 운영 전 필수 | 소스 릴리즈 확정 | 미커밋/미추적 소스 포함 여부 확정, 커밋/빌드 해시/보고서 보관 | 개발 담당 지정 |
| 운영 정책 확정 | 보관 기간 | 대화 삭제 고정 90일과 화면 조회 설정 구분. 기관 정책에 맞춰 코드 변경 필요 여부 결정 | 업무/운영 담당 지정 |
| 운영 정책 확정 | 백업 운영 자동화 | OS 예약, 외부 보관/암호화/알림, 실제 RPO/RTO 검증. 문서 목표와 운영 증빙 구분 | DB/운영 담당 지정 |
| 기능 범위 확정 | 온톨로지 연계 | 제공 API/개념·관계/ID/버전·권한, 검색 매핑·동기화 설계/구현 | 업무/연계 담당 지정 |
| 기능 범위 확정 | 외부 REST 확대 | status 외 서비스 등록/문서 수신/통계 계약 확정 후 구현 | 연계 담당 지정 |
| 문구 개선 | 검색 설정 도움말 | SEARCH_DISPLAY/SEARCH_CRAWL의 초과 시 적용 표현, SEARCH_MIN_SCORE의 최상위 1건 fallback 표현을 실제 선별 동작과 맞추기 | 개발 담당 지정 |
| 운영 고도화 | 다중 앱 인스턴스 | 메모리 rate limit/동시 수집 제한/파일 공유/스케줄 점유 검수 | 개발/인프라 담당 지정 |
| 문서 고도화 | DB COMMENT 보완 | 명세의 `소스 보완` 설명을 검토 후 신규 migration으로 COMMENT 등록 | 개발/DB 담당 지정 |
