## 구현 범위 구분

| 연계 | 현재 구현 | 아직 필요한 확인/작업 |
|---|---|---|
| 독립 로그인 | LOCAL, 기존 계정/비밀번호/권한 | 인수할 로컬 ADMIN, IP 정책 |
| Gateway SSO | 매 요청 헤더 검증, 사번 기반 JIT 계정, 서비스 역할 적용, 모드별 로그인 | 실제 Gateway 헤더/프록시/리다이렉트/로그아웃 종단 검수 |
| vLLM | `/v1/models`, `/v1/chat/completions`, timeout/fallback | 실제 주소/모델/키, 응답 품질·부하·전송할 자료 범위 |
| 외부 REST | 별도 API 키 인증, `/external/api/v1/status` | 서비스 등록·문서 전달·통계 등 구체 API 계약 및 구현 |
| 외부 온톨로지 | 현재 별도 클라이언트·개념 관계 매핑 구현 없음 | 제공 시스템 API/스키마, ID·개념 매핑, 검색 활용, 동기화·장애 규칙 |

vLLM endpoint를 설정하고 Gateway가 JSON/HTTP 파라미터를 전달하는 것만으로 온톨로지 연동이 완료되지는 않는다. 기획 가이드의 전체 요구사항을 현재 구현 완료 목록으로 인계하지 않는다.

## Gateway 요청 계약

시스템 설정을 GATEWAY로 저장하려면 Gateway URL, 서비스 ID, 서버 `CLEVERCHAT_GATEWAY_SHARED_SECRET`을 준비한다. 신뢰된 Gateway가 인증을 완료한 후 앱으로 보내는 헤더는 다음과 같다.

| 헤더 | 규칙 |
|---|---|
| `X-Clever-Gw-Secret` | 서버의 공유 시크릿과 일치. 브라우저/일반 클라이언트에 배포하지 않음 |
| `X-Clever-User` | 사번, 필수, 64자 이하, 제어문자 금지 |
| `X-Clever-Roles` | `cleverchat=OPERATOR;other-service=USER` 형태. 설정 서비스 ID에 해당하는 ADMIN/OPERATOR/USER 한 값. 헤더 8192자 이하, 같은 서비스 중복 거부 |
| `X-Clever-Admin` | 정확히 `1`이면 ADMIN으로 처리. 신뢰 경계에서 위조가 불가능해야 함 |
| `X-Clever-Name` | 선택, UTF-8 percent encoding. 디코딩 후 100자 이하. 공백이면 사번 사용 |
| `X-Clever-Unit` | 선택, UTF-8 percent encoding. 디코딩 후 200자 이하 |

이름/조직의 `+`는 공백이 아니라 실제 +로 보존된다. 역할 누락·미지원 역할은 허용되지 않는다(정상 관리자 override 제외). 공유 시크릿이 맞아도 계정의 `use_yn=N`이면 거절한다.

앱은 사번으로 GATEWAY 계정을 만들고 비밀번호를 저장하지 않는다. 매 요청에서 신원과 역할을 다시 확인해 HTTP 세션에 반영한다. LOCAL 계정이 자동 삭제되거나 로컬 비밀번호로 GATEWAY 인증을 대체하지 않는다.

예외 경로는 `/asset/`, `/actuator/`, `/external/`, `/error`, `/favicon.ico`다. 이 중 외부 API는 자체 키 인증을 적용한다. health를 SSO로 보호한다고 가정하지 말고 네트워크 노출 범위를 별도로 정한다.

## 로그인·로그아웃·프록시

- GATEWAY에서 헤더 없는 `GET /login`은 연계 로그인 안내 화면으로 연결한다. 일반 페이지의 헤더 없는 GET은 로그인으로 이동할 수 있고 API/잘못된 인증은 401 `SSO_REQUIRED`로 반환한다.
- GATEWAY의 `/login`에서 유효한 신원이 있으면 ADMIN/OPERATOR는 `/admin`, USER는 `/chat`으로 이동한다.
- `POST /logout`은 CSRF 보호하에 앱 세션을 정리한 후 현재 설정한 Gateway URL로 이동한다. **Gateway 전체 세션을 종료하는 전용 통합 로그아웃 호출은 구현되어 있지 않다.**
- 외부 사용자의 `X-Clever-*` 및 Forwarded 헤더를 그대로 앱에 전달하지 않는다. Gateway가 인증 결과로 재작성하고 앱 직접 포트는 신뢰된 프록시에서만 접근하도록 구성한다.
- context path를 사용한다면 프록시가 해당 prefix를 유지해야 한다. HTTPS 쿠키·세션·CSRF·정적 자원·리다이렉트를 같은 경로에서 검수한다.
- 모드 변경은 기존 세션을 무효화한다. 연계 장애 복구는 [LOCAL 전환 절차](../03.운영매뉴얼/운영_장애대응.md)를 이용하며 별도 무인증 우회 URL은 없다.

## vLLM 요청 계약

시스템 설정 AI 탭에서 API 기본 주소(`/v1` 끝), 모델명, 사용 여부, timeout/토큰/temperature를 저장한다. 필요하면 서버에 `CLEVERCHAT_VLLM_API_KEY`를 지정한다.

| 호출 | 규격 |
|---|---|
| 연결 확인 | `GET <base-url>/models`, 응답 `data[].id`에 저장한 모델명이 있는지 확인 |
| 답변 생성 | `POST <base-url>/chat/completions`, JSON의 model/messages/max_tokens/temperature/stream=false |
| 인증 | 키가 있으면 `Authorization: Bearer <key>` |
| 응답 사용 | `choices[0].message.content`를 읽음 |
| 제한 | 접속 timeout 5초, 응답 timeout 기본 60초(설정 가능), redirect 따르지 않음, 응답 최대 2,000,000바이트 |
| 실패 | 오류·timeout·빈 답변 시 기존 검색 근거 답변 사용. 다른 외부 AI로 자동 전환하지 않음 |

검색 근거가 있어야 생성한다. 질문은 최대 2,000자, 근거는 최대 10건의 제목(300자)/snippet(3,000자)을 구성해 전송하고 답변은 최대 32,000자로 제한한다. 모델 목록 조회 성공은 실제 생성·품질·처리량을 보장하지 않으므로 실제 질문과 장애 시 fallback을 별도 검수한다.

## 외부 REST

현재 제공 경로는 `GET /external/api/v1/status`다. 기본 비활성이며 `CLEVERCHAT_EXTERNAL_API_ENABLED`와 `CLEVERCHAT_EXTERNAL_API_KEY_SHA256`가 필요하다. 원문 API 키는 `Authorization: Bearer ...` 또는 `X-CleverChat-Api-Key`로 전달한다. Bearer 헤더가 있으면 우선 사용한다. 이 키는 Gateway 공유 시크릿 및 vLLM 키와 서로 다른 목적이다.

인증·비활성 상태와 응답 규격은 [M10 외부 REST 기반 코드 문서](../../2.설계/03.API설계서/M10_외부REST_API_Scaffold.md) 및 [컨트롤러](../../3.개발/cleverchat/src/main/java/kr/co/cleverchat/domain/externalapi/ExternalApiController.java)를 확인한다. 챗봇 내부 관리자 API를 외부 시스템 계약으로 임의 공개하지 않는다.

## 상대 시스템 담당자에게 받아야 할 것

| 항목 | 확정할 내용 | 현 상태 |
|---|---|---|
| Gateway | 환경별 URL, service ID, 헤더 형식, 신뢰 IP, 비밀 전달/교체, 로그인 복귀 위치 | 현장 값 미확정 |
| 통합 로그아웃 | 앱 세션/중앙 세션 종료 범위, 전용 경로, 재로그인 동작 | 계약 필요 |
| 서비스 등록 | 프로젝트 등록 방식, 상태/메뉴/권한 연계, 호출 주체/인증 | 전체 구현 계약 필요 |
| vLLM | 환경별 `/v1`, 모델 ID, 인증, timeout/동시 요청, 전송 자료 정책 | 실제 서버 검수 필요 |
| 온톨로지 | HTTP/API 문서, 개념/관계/문서 ID 예제, 버전, 권한, 조회/동기화 주기 | 미정 |
| 데이터 전달 | JSON 규격 버전, 원문 URL·문서 ID·삭제/수정 신호, 중복/재시도 규칙 | 미정 |

인수 검수에서는 정상 ADMIN/OPERATOR/USER, 역할 없음/중복/위조, 비활성 계정, 세션 전환, Gateway 장애, vLLM timeout을 포함한다. 실제 시크릿이나 사번을 검수 문서에 평문으로 첨부하지 않는다.
