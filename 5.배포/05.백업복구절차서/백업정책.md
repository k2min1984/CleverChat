# CleverChat 백업 정책

## 1. 범위

- 대상 DB: CleverChat 운영 PostgreSQL 데이터베이스 전체
- 대상 스키마: Flyway가 관리하는 애플리케이션 스키마와 Spring Session 테이블
- 제외: 애플리케이션 로그, 외부 수집기 저장소, OS 계정/비밀값 원문

## 2. 백업 방식

- 기본 백업은 PostgreSQL `pg_dump -Fc --no-owner --no-acl` custom format을 사용한다.
- 운영 샘플 스크립트는 `3.개발/cleverchat/deploy/backup/` 아래의 PowerShell/Linux 스크립트를 기준으로 한다.
- DB 접속 정보는 `PGHOST`, `PGPORT`, `PGDATABASE`, `PGUSER`, `PGPASSWORD` 환경변수로만 주입한다.
- 백업 산출물은 `CLEVERCHAT_BACKUP_DIR`에 저장하며, `.dump`와 `.sha256` checksum을 함께 보관한다.

## 3. 보존 기준

- 기본 보존 기간: 14일
- 최소 보존 기간: 7일
- 장기 보존, 외부 스토리지 업로드, 백업 파일 암호화는 후속 운영 결정 항목이다.

## 4. 암호화 키 보관

필드 암호화 컬럼은 DB 백업만으로 복구할 수 없다. 다음 값은 DB 백업과 별도 보안 저장소에 함께 보관한다.

- `CLEVERCHAT_FIELD_ENCRYPTION_KEY_BASE64`
- `CLEVERCHAT_FIELD_ENCRYPTION_KEY_ID`
- 키 회전 중이면 `CLEVERCHAT_FIELD_ENCRYPTION_PREVIOUS_KEYS`

키 material은 문서, 로그, 티켓, Git 저장소에 기록하지 않는다.

## 5. 실행 시점

- 정기 백업: 운영 정책에 따라 OS scheduler, cron, systemd timer, Windows Task Scheduler에서 실행한다.
- 배포 전 백업: Flyway migration이 포함된 배포 전에는 반드시 수동 백업과 checksum 확인을 수행한다.
- 장애 전환 전 백업: 운영 DB가 접근 가능하면 복구 작업 전 현재 상태 백업을 별도 이름으로 남긴다.
