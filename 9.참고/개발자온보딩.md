# 개발자 온보딩

> 목적: 신규 개발자가 CLEVERCHAT 로컬 개발 환경을 동일하게 구성하고, 운영 배포 방식과 개발용 Docker 사용 범위를 혼동하지 않도록 한다.

## 1. 필수 도구

| 도구 | 기준 |
|---|---|
| JDK | 17 LTS |
| Maven | 프로젝트 포함 `./mvnw` 우선 사용 |
| Docker Desktop 또는 Docker Engine | 로컬 PostgreSQL과 Testcontainers 실행용 |
| Git | 소스 형상관리 |

Windows 환경에서는 Docker Desktop 실행 후 Docker 데몬이 올라온 상태에서 아래 절차를 진행한다.

## 2. 저장소 위치

현재 기준 작업 경로:

```text
C:\02.Project\02.자바\01.WorkSpace\CLEVERCHAT
```

애플리케이션 루트:

```text
3.개발/cleverchat
```

## 3. 로컬 PostgreSQL 기동

```bash
cd 3.개발/cleverchat
docker compose -f docker/docker-compose.yml up -d
docker compose -f docker/docker-compose.yml ps
```

로컬 개발 DB 접속 정보:

| 항목 | 값 |
|---|---|
| Host | `localhost` |
| Port | `5433` |
| Database | `cleverchat` |
| User | `cleverchat` |
| Password | `cleverchat` |

이 값은 개발 전용이다. 운영과 검증 환경은 물리 PostgreSQL, 환경변수, 외부 properties 파일을 사용한다.

## 4. 애플리케이션 실행

```bash
cd 3.개발/cleverchat
./mvnw -DskipTests package
java -Dspring.profiles.active=dev -jar target/cleverchat.jar
```

브라우저에서 `http://localhost:8080`으로 접속한다. 부팅 시 Flyway가 마이그레이션을 자동 적용한다.

기본 관리자 계정은 Flyway 마이그레이션으로 DB에 생성된다.

| 항목 | 값 |
|------|----|
| URL | `http://localhost:8080/login` |
| ID | `admin` |
| Password | `admin` |

## 5. 테스트 실행

일반 단위 테스트:

```bash
cd 3.개발/cleverchat
./mvnw test
```

Windows PowerShell:

```powershell
cd 3.개발/cleverchat
.\mvnw.cmd test
```

기본 테스트는 `@Tag("integration")`이 부착된 PIT(Testcontainers 통합 테스트)를 제외하므로 Docker Desktop 없이 실행 가능해야 한다.

통합 테스트는 Testcontainers가 PostgreSQL 16 컨테이너를 띄우므로 실행 전 Docker Desktop이 기동되어 있어야 한다. 미기동 상태에서는 컨테이너 생성 단계에서 즉시 실패한다.

통합 테스트 포함:

```bash
cd 3.개발/cleverchat
./mvnw -Pit test
```

Windows PowerShell:

```powershell
cd 3.개발/cleverchat
docker info
.\mvnw.cmd -Pit test
```

통합 테스트만 단독 실행:

```powershell
cd 3.개발/cleverchat
.\mvnw.cmd -Pit -Dgroups=integration test
```

통합 테스트는 Testcontainers가 PostgreSQL 16 컨테이너를 자동으로 띄운다. Docker 데몬이 꺼져 있으면 `Could not find a valid Docker environment` 또는 Windows 기준 `Cannot connect to the Docker daemon at npipe:////./pipe/docker_engine` 오류로 실패한다.

### 5.1 Windows 진단

1. `docker info`로 Docker daemon 응답과 exit code 0을 확인한다.
2. `docker run --rm hello-world`로 컨테이너 기동 가능 여부를 확인한다.
3. `docker pull postgres:16`으로 이미지 수신 가능 여부를 확인한다.
4. 위 단계가 모두 정상이고도 실패하면 코드 결함으로 보고 결함 티켓을 등록한다.

## 6. 마이그레이션 클린 검증

Flyway 마이그레이션을 빈 DB에 처음부터 다시 적용하려면 로컬 개발 DB 볼륨을 삭제한다.

```bash
cd 3.개발/cleverchat
docker compose -f docker/docker-compose.yml down -v
docker compose -f docker/docker-compose.yml up -d
java -Dspring.profiles.active=dev -jar target/cleverchat.jar
```

`down -v`는 로컬 개발 데이터만 삭제한다. stage/prod DB에는 사용하지 않는다.

## 7. 운영 방식과의 차이

| 구분 | dev | stage/prod |
|---|---|---|
| 앱 배포 | 로컬 실행 | 실행 가능 JAR + systemd |
| DB | Docker PostgreSQL 16 | 물리 PostgreSQL |
| HTTPS | 미사용 | nginx 종단 |
| 시크릿 | 개발용 기본값 | 환경변수 또는 외부 properties |
| Docker | DB 재현성과 테스트용 | 사용하지 않음 |

Docker 관련 상세 절차는 `3.개발/cleverchat/docker/README.md`를 기준으로 한다.
