# M5 크롤링 운영 메모

## 실행 정책
- 크롤링 대상은 `/admin/crawl-targets`에서 등록하고, 수동 실행 또는 자동 실행으로 수집한다.
- 자동 실행은 Spring `@Scheduled` 단일 인스턴스 기준이며, target별 `INTERVAL` 또는 `CRON` 모드를 지원한다.
- `INTERVAL`은 5~10080분 범위를 허용한다.
- `CRON`은 Spring 6-field cron 표현식 기준이며, 최소 실행 간격은 5분 이상이어야 한다.
- 관리자는 `/admin/api/crawl-targets/schedule/preview`로 저장 전 다음 5회 실행 시각을 확인할 수 있다. 화면에서는 `/admin/crawl-targets`의 Preview 버튼이 같은 API를 사용한다.
- cron 다음 실행 시각 계산 실패 시 해당 target의 `next_run_at`을 비워 자동 재시도 반복을 막는다. Quartz, 클러스터 lock, timezone 선택 UI는 후속 범위다.
- 수집 전 `robots.txt`를 `CleverChatCrawler` user-agent 기준으로 확인한다. 명시 차단은 실패 처리하고, 조회 실패는 메시지에 남긴 뒤 수집을 계속한다.
- `robots.txt`는 origin 단위로 10분 TTL 캐시를 사용한다. 같은 origin의 robots 본문은 TTL 안에서 재사용하되, allow/disallow 판정은 요청 URL path별로 다시 계산한다.
- SSRF 방어 기본값은 `localhost`, private IP, link-local, multicast, userinfo 포함 URL 차단이다.
- 로컬/내부망 사이트를 크롤링해 챗봇 fallback을 검증해야 할 때는 dev/test에서만 `CLEVERCHAT_CRAWL_ALLOWED_HOSTS=localhost,127.0.0.1,<internal-host>`처럼 exact host allowlist를 지정한다. stage/prod는 기본 차단을 유지하고, 운영 허용이 필요하면 보안 검토 후 host 단위로만 연다.

## 크롤링 기반 챗봇 수동 검증
- 개발 환경은 `application-dev.yml`에서 HTTP 로컬 테스트를 위해 session cookie `secure=false`를 사용한다. stage/prod는 HTTPS 종단 전제로 `secure=true`를 유지한다.
- 관리자 로그인 후 `/admin/crawl-targets`에서 공개 URL 또는 allowlist에 등록된 로컬/내부망 URL을 등록하고 수동 실행한다.
- `/admin/crawl-documents`에서 `SUCCESS` 문서와 title/content preview를 확인한다.
- 검색 운영 화면 또는 검색 API에서 수집 문서의 고유 키워드가 `CRAWL_DOCUMENT` 결과로 반환되는지 확인한다.
- `/chat`에서 활성 게시 시나리오 세션을 시작한 뒤 같은 키워드를 자유 입력한다. 검색 결과가 있으면 기존 M4 fallback 안내가 반환되고, 결과가 없을 때만 `NO_MATCH` 실패 큐가 기록되어야 한다.
- 활성 게시 시나리오가 없는 신규 DB에서는 관리자 시나리오 화면에서 최소 그래프를 저장, 게시, 활성화한 뒤 챗봇 검증을 진행한다.

## 실패 확인
- 실패 실행 로그는 `/admin/crawl-runs`와 `/admin/api/crawl-runs/failures`에서 확인한다.
- 실행 로그는 `failure_code`로 원인을 분류한다. 기준 코드는 `ROBOTS_BLOCKED`, `HTTP_ERROR`, `TIMEOUT`, `PARSE_ERROR`, `DUP_HASH`, `FETCH_ERROR`, `NOT_HTML`, `URL_BLOCKED`, `SCHEDULE_INVALID`, `SYSTEM_ERROR`다.
- `/admin/crawl-runs`, `/admin/api/crawl-runs`, `/admin/api/crawl-runs/failures`는 `failureCode` 필터를 지원한다.
- 관리자는 실패 건을 확인 처리할 수 있으며, webhook 외부 알림 기본형은 M6 운영 관측 기준을 따른다.

## 보존 정리
- 실행 로그 기본 보존 기간은 365일이다.
- 실패/중복 수집 문서 기본 보존 기간은 90일이다.
- `/admin/api/crawl-runs/expired`는 dry-run으로 예상 삭제 건수를 먼저 확인할 수 있다.
- 자동 정리는 매일 03:45에 실행한다.
