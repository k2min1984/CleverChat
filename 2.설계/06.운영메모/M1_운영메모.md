## 초기 관리자 생성

> 정책 메모: V2의 기본 관리자 시딩 관련 주석은 과거 정책이며 현재는 `V4_1` + profile placeholder 정책을 기준으로 한다. 마이그레이션 파일(V2 계열) 내에 남아 있는 시딩 관련 주석/문구는 이력 보존 목적의 잔존 텍스트이므로, 운영/검증 절차는 본 문서의 V4_1 기준을 따른다. V2 파일 본문을 직접 고치면 이미 적용된 DB에서 Flyway checksum mismatch가 발생할 수 있으므로, 변경 이력은 후속 마이그레이션 또는 운영 문서 메모로 남긴다.

> V4_2 보강: V2 잔존 주석 정합 보강은 `3.개발/cleverchat/src/main/resources/db/migration/V4_2__document_admin_seed_policy_change.sql`로 명문화한다. V4_2는 스키마/데이터를 바꾸지 않는 정책 명문화 전용 마이그레이션이며, V2 본문은 그대로 둔다.

기본 관리자 계정은 Flyway `V4_1__seed_default_admin.sql`로 DB에 생성한다. 별도 환경변수 주입은 필요 없다.

- dev/stage: `spring.flyway.placeholders.default-admin-seed-enabled=true`로 `admin/admin` 계정을 생성 또는 갱신한다.
- prod: `application-prod.yml`의 `spring.flyway.placeholders.default-admin-seed-enabled=false`로 기본 관리자 계정을 자동 생성하지 않는다. 운영 반영 전 별도 운영 시딩 정책 또는 비밀번호 변경 절차를 확정한다.

| 항목 | 값 |
|------|----|
| username | `admin` |
| password | `admin` |
| role | `ADMIN` |

동일 username이 이미 있으면 마이그레이션은 비밀번호, 표시명, 활성 상태, 실패 횟수, 잠금 상태를 로그인 가능한 기본값으로 갱신하고 ADMIN 권한을 보장한다. 개발/검증 편의 계정이므로 운영 배포 전에는 비밀번호 변경 또는 별도 운영 시딩 정책을 확정해야 한다.

## 로컬 검증

1. PostgreSQL 개발 컨테이너를 실행한다. 절차는 `3.개발/cleverchat/docker/README.md`를 기준으로 하며, 이 컨테이너는 개발 전용이다.
2. 애플리케이션을 실행해 Flyway 마이그레이션을 적용한다.
3. `/login`에서 `admin/admin`으로 로그인한다.
4. `/admin` 진입 여부를 확인한다.
5. 실패 로그는 `login_log`, 세션은 `SPRING_SESSION`, 관리자 작업 감사는 `audit_log`에서 확인한다.

## Flyway 적용 이력 점검

V2 baseline 파일은 운영/공유 DB에 적용된 뒤 본문을 수정하지 않는다. 적용 이력은 다음 SQL로 확인한다.

```sql
SELECT installed_rank, version, description, success, checksum, installed_on
FROM flyway_schema_history
WHERE version = '2';
```

`version='2'` 행이 있고 `success=true`이면 V2의 잔존 주석은 이력 보존 텍스트로 취급한다. checksum 불일치가 발견되면 `flyway repair` 또는 `validateOnMigrate=false`를 먼저 적용하지 말고, 원인 파일 diff와 적용 DB 범위를 확인한다.

운영 배포 또는 stage 승격 직후에는 `admin/admin` 로그인이 가능하지 않아야 한다. 가능하면 배포를 차단하고 계정 비활성/삭제, 비밀번호 변경, Flyway placeholder 설정을 함께 확인한다.

## Docker 사용 경계

- dev: PostgreSQL 16 재현성과 Flyway 클린 검증을 위해 Docker Compose를 사용한다.
- test: Testcontainers가 PostgreSQL 16 임시 컨테이너를 사용한다.
- stage/prod: 물리 PostgreSQL, 실행 가능 JAR, systemd, nginx HTTPS 종단을 사용하며 Docker Compose를 사용하지 않는다.
- 개발용 DB 비밀번호(`cleverchat/cleverchat`)는 운영 문서나 배포 스크립트로 복사하지 않는다.

## 남은 운영 과제

- 관리자 비밀번호 변경 화면
- 잠금 해제/계정 비활성화 관리 화면
- 감사 로그 조회 화면
- 운영 로그 보존 기간 및 백업 정책
