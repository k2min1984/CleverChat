# M7 보안 헤더 운영 메모

## 적용 범위

- 애플리케이션 공통 `SecurityHeadersFilter`가 HTML 화면, `/admin/api/**`, `/chat/api/**`, `/actuator/health` 응답에 동일한 브라우저 보안 헤더를 적용한다.
- 신규 DB, API envelope, 인증/CSRF 인터셉터 정책은 변경하지 않는다.

## 공통 헤더

- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `Referrer-Policy: strict-origin-when-cross-origin`
- `Permissions-Policy: camera=(), microphone=(), geolocation=()`
- `Content-Security-Policy: default-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; form-action 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'`

## HTTPS/HSTS 기준

- 운영 HTTPS 종단과 HTTP to HTTPS redirect는 온프레미스 nginx가 담당한다.
- 애플리케이션은 기존처럼 `server.forward-headers-strategy=framework`를 유지한다.
- `Strict-Transport-Security: max-age=31536000; includeSubDomains`는 Spring active profile에 `prod`가 포함될 때만 응답에 추가한다.

## CSP 예외 기준

- 외부 script/style/image/font/connect 도메인은 기본 허용하지 않는다.
- 외부 리소스가 필요하면 사용 목적, 도메인, 데이터 반출 가능성, 장애 시 영향, 대체 방안을 문서화한 뒤 CSP에 명시적으로 추가한다.
- `/chat` 임베드 위젯은 `frame-ancestors 'none'` 때문에 현재 범위에서 허용하지 않는다. 위젯 제공은 CORS, 쿠키, CSRF, CSP를 별도 설계한 뒤 진행한다.

## 운영 확인 절차

- 배포 후 HTML 화면, `/admin/api/**`, `/chat/api/**`, `/actuator/health`에서 공통 보안 헤더가 유지되는지 확인한다.
- dev/stage에서는 HSTS가 없어도 정상이다. prod에서만 HSTS가 있어야 한다.
- nginx HTTPS redirect 설정은 애플리케이션 배포와 별도 운영 체크리스트에서 확인한다.

## Chat Embed Launcher Baseline

- Embed v1 is launcher-only: external pages may show a button or link that opens `/chat` in a new window.
- iframe embedding remains blocked by `frame-ancestors 'none'` and `X-Frame-Options: DENY`.
- External `/chat/api/**` calls remain blocked by same-origin/CORS and existing CSRF policy.
- Before an iframe allowlist or JS widget runtime is introduced, document allowed origins, cookie SameSite/Secure behavior, CSRF strategy, CSP changes, and rate-limit impact.
