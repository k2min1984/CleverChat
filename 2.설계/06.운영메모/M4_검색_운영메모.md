# M4 검색 운영 메모

> 작성일: 2026-05-11
> 대상: PostgreSQL FTS 검색, 검색 로그, 인기 검색어 집계, 보존 배치

## 1. 확정 기준

- 검색 엔진은 PostgreSQL FTS `simple` configuration, `pg_trgm`, `unaccent` 조합을 사용한다.
- 검색 로그와 차단 로그는 90일 보존한다.
- 인기 검색어 집계는 매일 KST 03:30 실행한다.
- 검색 결과 캐시는 사용하지 않는다.
- PII 차단 로그에는 원문 검색어를 저장하지 않는다.

## 2. 모니터링 지표

| 지표 | 임계 후보 | 조치 |
|---|---:|---|
| 검색 p95 지연 | 500ms 초과 | 실행계획과 GIN 인덱스 사용 여부 확인 |
| 무결과율 | 20% 초과 | 키워드/유사어 보강 또는 형태소 분석 재검토 |
| 로그 폐기율 | 5% 초과 | 비동기 큐 크기와 DB write latency 확인 |
| PII 차단 건수 | 일 20건 초과 | 유입 경로와 오탐 패턴 확인 |

### 2.1 큐 폐기 메트릭/임계치

| 메트릭 | Micrometer 이름(권장) | 임계치 | 단계별 조치 |
|---|---|---:|---|
| 큐 폐기 건수(누적) | `cleverchat_search_log_queue_dropped_total` | 일 100건 | 큐 capacity·flush 주기 점검 |
| 큐 폐기율(min) | `dropped/(accepted+dropped)` 1분 이동평균 | 1% | WARN 알림, DB write latency 확인 |
| 큐 폐기율(min) | 위와 동일 | 5% | CRITICAL, capacity 즉시 상향 또는 flush 주기 단축 |
| 큐 점유율 | `queue_size / capacity` | 80% | flush 배치 size·worker 수 점검 |
| 큐 점유율 | 위와 동일 | 95% | CRITICAL, capacity 상향 |
| flush 실패율 | `cleverchat_search_log_flush_failed_total` | 5분 5건 | DB 커넥션 풀·트랜잭션 시간 확인 |

## 3. 운영 쿼리

검색 지연 상위:

```sql
select id, normalized_query, result_count, source, latency_ms, created_at
from search_log
order by latency_ms desc
limit 20;
```

무결과율:

```sql
select
    count(*) filter (where result_count = 0)::decimal / nullif(count(*), 0) as no_result_rate
from search_log
where created_at >= now() - interval '1 day';
```

보존 기간 초과 로그:

```sql
select count(*) from search_log where created_at < now() - interval '90 days';
select count(*) from search_block_log where created_at < now() - interval '90 days';
```

## 4. 장애 대응

- 확장 설치 실패: Flyway 적용을 중단하고 DBA 권한으로 `pg_trgm`, `unaccent` 설치 가능 여부를 확인한다.
- 검색 지연 증가: `EXPLAIN (ANALYZE, BUFFERS)`로 FTS/trigram 인덱스 사용 여부를 확인한다.
- 한국어 품질 저하: 무결과 로그와 클릭/선택 전환율을 확인하고 형태소 분석 도입 트리거를 검토한다.
- 로그 큐 포화: 검색 응답은 유지하고 폐기 카운터를 노출한다. 5% 초과 시 큐와 flush 설정을 조정한다.
