## 2. 공통 운영 화면 기준

- 관리자 화면은 데스크톱 우선으로 설계하되 768px 이하에서는 테이블 가로 스크롤 또는 요약 카드로 정보를 보존한다.
- 모든 상태 변경 요청은 CSRF 토큰을 포함한다.
- 응답과 화면에는 `anonymous_id`, IP, User-Agent 원문을 표시하지 않는다.
- 저장/검토/삭제 결과는 `role="status"`와 `aria-live="polite"` 영역으로 알린다.
- 오류는 입력 필드 인근에 표시하고 즉시 조치해야 하는 오류만 `role="alert"`를 사용한다.

## 4. 화면별 명세

### 4.1 `ADM-CHAT-001` 세션 목록

- URL/권한: `/admin/chat/sessions`, ADMIN/OPERATOR
- 주요 컴포넌트: 상태/시나리오/기간 필터, 세션 테이블, 페이지네이션
- API: `GET /admin/api/chat/sessions`
- 개인정보: 원문 식별자를 표시하지 않고 내부 세션 ID와 마스킹 요약만 표시한다.
- 접근성: 테이블은 `th scope="col"`을 사용하고 결과 수를 텍스트로 제공한다.

### 4.2 `ADM-CHAT-002` 세션 상세

- URL/권한: `/admin/chat/sessions/{id}`, ADMIN/OPERATOR
- 주요 컴포넌트: 세션 메타, 메시지 트레이스, 실패/피드백 연결. 1차 구현은 상태 전이 타임라인 대신 현재 상태와 메시지 순서를 표시한다.
- API: `GET /admin/api/chat/sessions/{id}`
- 개인정보: `anonymous_id`, IP, UA 원문 미노출. 해시 일부 또는 내부 ID만 표시한다.
- 접근성: 메시지 방향과 seq를 텍스트로 제공한다.

### 4.3 `ADM-CHAT-003` 실패 큐

- URL/권한: `/admin/chat/failures`, ADMIN/OPERATOR
- 주요 컴포넌트: reviewed 필터, reason 필터, 실패 목록, 처리 버튼, 검토 코멘트 입력
- API: `GET /admin/api/chat/failures`, `POST /admin/api/chat/failures/{id}/review`
- 감사: 검토 처리는 `CHAT_FAILURE_REVIEW` 감사 로그 대상이다.
- 접근성: 처리 결과는 `role="status"`로 알리고 코멘트 입력은 label을 연결한다.

### 4.4 `ADM-CHAT-004` 피드백 목록

- URL/권한: `/admin/chat/feedback`, ADMIN/OPERATOR
- 주요 컴포넌트: rating 필터, 기간 필터, 코멘트 목록, 세션 상세 링크
- API: `GET /admin/api/chat/feedback`
- 보안: comment는 escape 표시만 허용한다.
- 접근성: `UP`/`DOWN`은 아이콘만 쓰지 않고 텍스트를 함께 제공한다.

### 4.5 `ADM-CHAT-005` 추천 질문 관리

- URL/권한: `/admin/chat/recommendations`, ADMIN/OPERATOR
- 주요 컴포넌트: 추천 질문 목록, 시나리오 선택, label 입력, priority 입력, enabled 토글, 등록/수정/삭제 버튼
- API: `GET/POST /admin/api/chat/recommendations`, `GET/PUT/DELETE /admin/api/chat/recommendations/{id}`
- 입력 기준: label 1~200자, priority 0~9999, scenarioId 양수
- 정렬 기준: priority ASC, id ASC
- 동작 기준: `enabled=false` 저장 즉시 `GET /chat/api/recommendations` 응답에서 제외한다.
- 접근성: enabled 토글은 현재 상태를 스크린리더가 인지할 수 있어야 하며 저장 결과는 `aria-live="polite"`로 알린다.

## 5. PR 수용 기준
