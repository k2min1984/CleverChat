# 접근성 체크리스트

> 작성일: 2026-05-08
> 기준: 관리자 M2 화면, M3 챗봇 화면, M4 검색 화면 공통

## 1. 공통

| 항목 | 기준 | 확인 방법 |
|---|---|---|
| 키보드 이동 | Tab 순서가 시각적 흐름과 일치 | 마우스 없이 이동 |
| 포커스 표시 | 현재 포커스가 명확히 보임 | 버튼/링크/입력 확인 |
| 명도 대비 | 일반 텍스트 WCAG AA 4.5:1 이상 | 브라우저 도구 또는 검사 도구 |
| 제목 구조 | `h1`부터 순차적 사용 | 스크린리더/DOM 확인 |
| 링크/버튼명 | 목적을 텍스트로 이해 가능 | 아이콘 버튼은 `aria-label` |
| 오류 인지 | 오류 메시지를 즉시 인지 가능 | `role="alert"` 또는 연결된 설명 |

## 2. 폼

| 항목 | 기준 |
|---|---|
| label | 모든 입력은 `label for` 또는 `aria-label` 연결 |
| 필수값 | 시각 표시와 `required`/검증 메시지 제공 |
| 오류 연결 | 입력별 오류는 `aria-describedby`로 연결 |
| 저장 결과 | 성공/실패 메시지는 포커스 이동 또는 live region으로 인지 |

## 3. 목록/테이블

| 항목 | 기준 |
|---|---|
| 테이블 헤더 | 데이터 테이블은 `th scope` 사용 |
| 페이징 | 현재 페이지와 이동 버튼 상태 제공 |
| 검색 결과 | 결과 없음/결과 수를 텍스트로 제공 |
| 행 액션 | 수정/삭제/게시 버튼명이 대상과 함께 이해 가능 |

## 4. M2 시나리오 화면

| 화면 | 필수 점검 |
|---|---|
| 시나리오 목록 | 검색폼 label, 결과 수, 페이징, 행 액션 이름 |
| 시나리오 등록 | 필수 입력 오류, 저장 실패 alert, 취소/저장 순서 |
| 시나리오 편집 | 노드 추가/삭제 키보드 접근, JSON textarea 설명 |
| 미리보기 | 버튼 선택 흐름 키보드 조작, 현재 단계 안내 |
| 비밀번호 변경 | 현재/새 비밀번호 label 연결, 정책 오류 `aria-describedby`, 성공/실패 메시지 live region |

## 5. 완료 기준

- 크롬/엣지에서 키보드만으로 주요 업무를 완료할 수 있다.
- 폼 오류가 스크린리더와 시각 사용자 모두에게 전달된다.
- 포커스가 모달/확인창 밖으로 새지 않는다.
- 색상만으로 상태를 구분하지 않는다.

## 6. M4 검색 화면

| 화면 | 필수 점검 |
|---|---|
| 검색 로그 | 필터 label, 결과 수 안내, 페이징 현재 위치, 표 헤더 |
| PII 차단 검색 | 원문 미노출 안내, PII 유형 텍스트 표시, 기간 필터 접근성 |
| 인기 검색어 | 날짜 선택 label, 재집계 버튼명, 무결과 수/검색 수 컬럼 헤더 |

## 7. M2 결정사항 9절 접근성 반영

- 최초 비밀번호 변경 화면은 `must_change_password=true` 사용자가 우회할 수 없는 흐름으로 제공하되, 현재 비밀번호/새 비밀번호/확인 입력과 정책 오류를 각각 `label`, `aria-describedby`, live region으로 연결한다.
- OPERATOR 비활성 시드 활성화 후 최초 로그인 사용자는 비밀번호 변경 필요 상태와 실패 사유를 키보드와 스크린리더로 동일하게 인지할 수 있어야 한다.
- 쿠키 보안 속성, 프록시 헤더, 매칭 캐시 TTL은 화면에 노출되는 안내 문구가 아니라 보안/운영 기준으로 검증하며, 화면 테스트에서는 로그인 유지, CSRF 실패 메시지, 저장 후 캐시 반영 지연 안내가 접근성 기준을 충족하는지 확인한다.
