# 감사 로그 표준

> 작성일: 2026-05-08

## 1. 기록 대상

| 영역 | 이벤트 |
|---|---|
| 인증 | 로그인 성공/실패, 로그아웃, 계정 잠금 |
| 권한 | 사용자 권한 변경, 계정 활성/비활성 |
| 시나리오 | 생성, 수정, 삭제, 버전 저장, 게시, 활성화 |
| 크롤링 | URL 등록/수정/삭제, 수동 실행, 스케줄 변경 |
| 운영 | 공지 등록/수정/삭제, 설정 변경 |
| 보안 | 접근 거부, 반복 실패, 비정상 요청 탐지 |

## 2. 필드 기준

| 필드 | 설명 |
|---|---|
| `actor` | 작업자 username. 비인증 사용자는 `anonymous` |
| `action` | 대문자 스네이크 케이스 이벤트 코드 |
| `target_type` | 대상 도메인명 |
| `target_id` | 대상 PK 또는 식별자 |
| `detail` | 변경 요약 JSON |
| `ip` | 클라이언트 IP. 프록시 환경은 신뢰된 헤더만 사용 |
| `created_at` | 서버 기준 발생 시각 |

## 3. detail 작성 규칙

```json
{
  "before": {"status": "INACTIVE"},
  "after": {"status": "ACTIVE"},
  "reason": "operator request"
}
```

- 비밀번호, 세션 ID, CSRF 토큰, API 키는 기록하지 않는다.
- 개인정보는 마스킹 후 기록한다.
- 대량 본문은 기록하지 않고 대상 ID와 변경 건수만 기록한다.
- 실패 이벤트도 가능한 범위에서 기록하되, 예외 stack trace는 애플리케이션 로그에만 남긴다.

| 로그 | 보존 기간 | 비고 |
|---|---:|---|
| 로그인 로그 | 1년 | 보안 감사 |
| 관리자 감사 로그 | 3년 | 공공 운영 기준 고려 |

| 검색/질문 로그 | 1년 | 개인정보 포함 시 마스킹/익명화 |
