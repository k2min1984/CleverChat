# 입력 검증 표준

> 작성일: 2026-05-08

## 1. 공통 원칙

- Controller DTO에 Bean Validation을 적용한다.
- Service에서 권한, 상태, 참조 무결성 등 업무 규칙을 검증한다.
- DB 고유 제약 위반은 409 응답으로 변환한다.
- 서버 로그와 응답에 민감정보를 포함하지 않는다.
- HTML 출력은 기본 이스케이프를 사용한다.

## 2. 필드별 기준

| 필드 유형 | 기준 |
|---|---|
| ID | 양수 `Long`, 존재 여부 서비스 검증 |
| 제목 | 1~200자, 제어문자 금지 |
| 설명/본문 | 0~10,000자, raw HTML 저장 금지 |
| 코드/키 | 영문/숫자/하이픈/언더스코어, 1~100자 |
| 상태값 | enum allow-list |
| URL | http/https만 허용, SSRF 검증은 M5에서 별도 적용 |
| 정렬값 | 0~9999 범위 |
| 검색어 | 1~100자, 과도한 와일드카드 제한 |

## 3. M2 시나리오 검증

| 대상 | 검증 |
|---|---|
| `ScenarioCreateRequest.title` | 필수, 200자 이하 |
| `ScenarioUpdateRequest.status` | 직접 변경 금지. 활성화 API 사용 |
| `VersionGraphSaveRequest.nodes` | 1개 이상, 500개 이하 |
| `nodeKey` | 버전 내 중복 금지 |
| `nodeType` | `QUESTION`, `ANSWER`, `BRANCH`, `END` 중 하나 |
| `options.nextNodeKey` | 같은 요청의 노드 키 또는 기존 노드 참조 |
| `keyword` | 시나리오 내 중복 금지 |
| `weight` | 1~100 범위 |

## 4. MyBatis SQL 기준

- 사용자 입력은 항상 `#{}`로 바인딩한다.
- 정렬 컬럼처럼 바인딩이 어려운 값은 서버 allow-list 매핑 후 사용한다.
- `LIKE` 검색어는 서버에서 escape 처리한다.
- 동적 SQL은 조건 누락 시 전체 테이블 스캔이 발생하지 않도록 기본 제한을 둔다.
