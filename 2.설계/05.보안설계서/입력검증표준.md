# 입력 검증 표준

> 작성일: 2026-05-08

## 1. 공통 원칙

- Controller DTO에 Bean Validation을 적용한다.
- Service에서 권한, 상태, 참조 무결성 등 업무 규칙을 검증한다.
- DB 고유 제약 위반은 409 응답으로 변환한다.
- 서버 로그와 응답에 민감정보를 포함하지 않는다.
- HTML 출력은 기본 이스케이프를 사용한다.

## 2. 필드별 기준

| 필드 유형 | 기준 |
|---|---|
| ID | 양수 `Long`, 존재 여부 서비스 검증 |
| 제목 | 1~200자, 제어문자 금지 |
| 설명/본문 | 0~10,000자, raw HTML 저장 금지 |
| 코드/키 | 영문/숫자/하이픈/언더스코어, 1~100자 |
| 상태값 | enum allow-list |
| URL | http/https만 허용, userinfo 금지, SSRF 기본 차단. dev/test 로컬·내부망 검증은 exact host allowlist로만 허용 |
| 정렬값 | 0~9999 범위 |
| 검색어 | 기본 1~100자. M4 fallback/관리자 검색어는 1~200자, 과도한 와일드카드 제한 |
| 목록 제한값 | 1 이상, 화면/API별 상한 적용. 검색 100, 감사/크롤 실행 로그 200 기준 |
| 보존 기간 | 최소 30일, 운영 API 최대 3650일 |
| 스케줄 interval | 5~10080분 |

## 3. M2 시나리오 검증

| 대상 | 검증 |
|---|---|
| `ScenarioCreateRequest.title` | 필수, 200자 이하 |
| `ScenarioUpdateRequest.status` | 직접 변경 금지. 활성화 API 사용 |
| `VersionGraphSaveRequest.nodes` | 1개 이상, 500개 이하 |
| `nodeKey` | 버전 내 중복 금지 |
| `nodeType` | `QUESTION`, `ANSWER`, `BRANCH`, `END` 중 하나 |
| `options.nextNodeKey` | 같은 요청의 노드 키 또는 기존 노드 참조 |
| `keyword` | 시나리오 내 중복 금지 |
| `weight` | 1~100 범위 |

## 4. MyBatis SQL 기준

- 사용자 입력은 항상 `#{}`로 바인딩한다.
- 정렬 컬럼처럼 바인딩이 어려운 값은 서버 allow-list 매핑 후 사용한다.
- mapper XML에서 `${}` 문자열 치환은 금지하며, 정적 테스트로 회귀를 차단한다.
- `LIKE` 검색어는 서버에서 escape 처리한다.
- 동적 SQL은 조건 누락 시 전체 테이블 스캔이 발생하지 않도록 기본 제한을 둔다.

## 5. M4 검색 검증

| 대상 | 검증 |
|---|---|
| fallback 검색어 | trim 후 1~200자 |
| 관리자 검색 테스트 | trim 후 1~200자, 결과 제한 1~20 |
| 검색 로그 필터 | 기간 범위와 페이지 크기 상한 적용 |
| PII 차단 | 주민등록번호/카드번호 등 고위험 패턴 차단, 원문 로그 저장 금지 |

## 6. M5/M6 운영 API 검증

| 대상 | 검증 |
|---|---|
| 크롤 대상 스케줄 | interval 5~10080분 |
| 크롤 실행 로그 조회 | `status` allow-list, `limit` 1~200 |
| 크롤 보존 삭제 | 보존 기간 30~3650일 |
| 감사 로그 조회 | actor/action/targetType 100자 이하, `limit` 1~200 |

## 7. 오류 응답 기준

- Bean Validation, query parameter 범위 오류, allow-list 오류는 `400 VALIDATION_ERROR`로 반환한다.
- 오류 응답에는 원문 요청 body, query string, SQL, stack trace, 민감정보를 포함하지 않는다.
- 파일 업로드 기능은 현재 없다. 업로드 기능 도입 시 MIME, 확장자, 크기, 악성코드 검사 기준을 별도 구현 전 완료 조건으로 둔다.
