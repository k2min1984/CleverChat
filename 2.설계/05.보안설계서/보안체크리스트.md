## CSRF 토큰 쿠키 예외 근거

- 자체 CSRF 인터셉터의 쿠키 기반 토큰은 서버가 발급한 토큰을 브라우저 JavaScript가 읽고 `X-CSRF-TOKEN` 헤더로 되돌려 보내는 패턴을 사용한다.
- 이 헤더 전송을 위해 CSRF 토큰 쿠키만 `HttpOnly=false`로 둔다. 세션 쿠키와 `anonymous_id` 같은 식별 쿠키는 `HttpOnly=true`를 유지한다.
- 예외 쿠키에도 `Secure=true`, `SameSite=Lax`를 적용하고, 토큰 값은 감사 로그, 운영 로그, 오류 응답, 관리자 API 응답에 포함하지 않는다.

## 관리자 native form CSRF 점검 기준

- `templates/admin/**`, `templates/admmgr/**` 하위 `method="post"` form은 `admmgr/common/_csrfHidden :: csrfHidden` fragment를 포함해야 한다.
- `ADM.Form.submit` 기반 상태 변경 제출은 `csrfToken`/`csrfFormId` hidden 값 또는 `X-CSRF-Token`/`X-CSRF-FormId` 헤더 제출 여부를 확인한다.
- `/logout`는 관리자 세션 보유 상태에서 수행되는 상태 변경 요청이므로 자체 CSRF 검증 대상이다.
- `/login`은 로그인 전 진입점이므로 현재 fragment 적용 대상에서 제외한다. 로그인 CSRF 별도 적용 여부는 인증 정책 변경 시 재검토한다.

## 운영 환경변수

- `CLEVERCHAT_OPERATOR_SEED_USERNAME`: 초기 OPERATOR 아이디
- `CLEVERCHAT_OPERATOR_SEED_PASSWORD`: 초기 OPERATOR 임시 비밀번호
- `CLEVERCHAT_OPERATOR_SEED_DISPLAY_NAME`: 초기 OPERATOR 표시명
- `CLEVERCHAT_OPERATOR_SEED_ENABLED`: 운영 기본값 `false`
- `CLEVERCHAT_OPERATOR_SEED_MUST_CHANGE_PASSWORD`: 운영 기본값 `true`
- `CLEVERCHAT_AUTH_MAX_FAILED_ATTEMPTS`: 로그인 실패 잠금 임계값
- `CLEVERCHAT_AUTH_LOCK_MINUTES`: 잠금 시간
- `CLEVERCHAT_CHAT_MATCH_CACHE_TTL_SECONDS`: 매칭 캐시 TTL. 기본값 300

## Flyway 보안 보완

- `V3__scenario_baseline.sql`: M2 시나리오 도메인 테이블만 포함한다.
- `V3_1__auth_must_change_password.sql`: `users.must_change_password BOOLEAN NOT NULL DEFAULT false`만 추가한다.
- OPERATOR 시더는 V3.1 적용 후 `enabled=false`, `must_change_password=true`를 기본값으로 사용한다.
